# 精度の目標値 — 全工程の「実用に足る」線 (2026-10-03、案)

> 状態: **案 (利用者の承認待ち)**。目標値は誤りの代償から決めた私案で、現状値は過去の実測の再掲。
> 測っていないものは「未測定」と書く。現状値の日付が古いものは、モデルや基準が変わった後の値ではない。
> 関連: 重要度の再設計 [importance_relevance_redesign.md](importance_relevance_redesign.md)。

## 1. 目的
各工程の正しさが、このツール全体の正しさになる。工程ごとに「ここまで来れば実用に足る」線を決め、
いまの値との差から改善の順番を決める。線が無いと、どこまで直せば終わりか判断できない。

## 2. 目標値の決め方
1. **誤りの代償の向きで、見る指標を分ける**
   - **見逃しが痛い工程** (重大な事象・日本関連・取り込み): 回収率 (拾うべきものを拾った割合) を高く置く。
     拾い過ぎは人が読んで捨てられるが、落としたものは二度と見えない
   - **混入が痛い工程** (統合・主題アクター・台帳の証拠・通知): 適合率 (拾ったもののうち正しい割合) を
     高く置く。統合のように戻しにくい操作や、誤った判断の材料になるものは混入を許さない
   - **生成物** (要約・事象ニュース・総括): 事実の誤り (書いてはいけないこと) と欠落 (書くべきことの抜け) を
     分けて数える。誤りは欠落より厳しく置く
2. **重い取り違えは別に数える** (例: S3 を S1 にする、high を low にする)。平均の正解率に埋もれさせない
3. **関門で保証できるものは 100% を目標にする** (引用の実在・禁止モデル等)。指示や学習に頼らない
4. 目標は**人どうしの一致を超えて置かない**。正解集が 1 つのモデル (Opus) の判定である以上、その揺れより
   細かい差は測れない

## 3. 測り方の約束 (すべての工程に共通)
- **正解は、いまの基準の版で裁定する** (Opus が本文を読み、基準の文に照らして判定)。基準を変えたら
  正解を付け直す。版の合わない正解・ラベルで測らない
- **境界 (基準の文からどちらとも言える) は別に数える**。境界の割合そのものにも目標を置く (≤ 20%)。
  境界が多いのはモデルの問題ではなく基準の文の問題で、精度の天井を決める
- **調整に使っていない記事で測る**。決まりごと・プロンプト・閾値を直すのに使った正解集で測った値は
  楽観的なので、「調整用」と「測定用」を分ける
- **目標は「1 日の件数 × 見逃し率 = 月に落とす件数」で確かめる** (2026-10-03 利用者指摘: S3 の見逃し 5% は多すぎる)
- **裁定役はコードで固定する**: Opus 5.5・エフォート中 (2026-10-03 に 4.8 / 5.5 中・高 / Sonnet 5.5 中・高 を
  40 件で比較。5.5 が基準の文を最も正確に当てはめ、中と高は 38/40 一致。Sonnet 5.5 は理由と結論の食い違いが
  3 件・境界の印が多い)。短縮名 (opus) は CLI の版で中身が変わり、エフォートは利用者の設定ファイルに左右される
  ため使わない。各行に裁定役・エフォート・基準の版を記録する。代わりのローカルモデルへ落ちる経路を通さない
- **件数**: 回収率 95% を確かめるには、正例が 60 件以上要る (60 件中 0〜1 件の見逃しで、下側の信頼限界が
  およそ 90%)。少数クラスは多めに抽出する
- **正解集そのものの確認**: 各正解集から 20〜30 件を、答えを伏せて人が読み、Opus との一致を見る
- **モデル・基準・決まりごとを変えたら測り直す**。結果は精度台帳に日付・版つきで残す

## 5. いまの差の大きいところ (改善の順番の案)
1. **台帳の証拠の割当 (61% → 80%)** と **関与国 (52% → 80%)**: 判断の材料そのものが外れている
2. **深刻度の軸 (69% → 85%)**: 深刻さ・detect の土台。s23 で本文から付け、欄を足す
3. **事象の群化 (83% → 90%)**: まとめ記事の切り離し (10-03) の効果を測ってから
4. **見立ての揺れ (20% → 5%)**: 10-02 の保留の仕組みの効果を測ってから
5. **未測定の工程** (要約の誤りと欠落・翻訳の正しさ・生成物の根拠・通知): まず測る

## 6. 測定の費用と計画
- 正解集 1 つ (150〜300 件) で Opus の週の枠の 3〜6%。全工程を一度に測ると 1 週間の枠を超える
- Opus の上限が戻る 10/7 の夜から、差の大きい順・未測定の順に、週ごとに分けて測る
- 結果は精度台帳 (工程 × 日付 × 版 × 値) に残し、目標との差をこの表に反映する

## 7. 利用者の判断が要る点
1. 各目標値の水準 (特に S3 の見逃し ≤ 5%・日本関連の見逃し ≤ 2%・統合の適合率 ≥ 95%)
2. 境界の割合の目標 (≤ 20%) — 基準の文を詰める作業の量が決まる
3. 測る順番 (§5)
