# 「同じ事象」の定義 (2026-10-22 利用者判断)

事象ニュースの群化・統合・関係・続報の表示・重複判定は、これまで段ごとに「同じ出来事か」の
意味が少しずつ違っていた (全体見直し 2026-10-22 の §1.3 / §2.5 / §3.6)。この文書が**定義の
SSoT**。判定のプロンプト・正解集・画面の文言は、ここに合わせて作り直す (今回は定義を固めて
食い違いを一覧にするところまで。プロンプトの直しは正解を作り直す段で行う)。

## 1. 定義

**1 つの事象 = 1 つの事案についての報道の束。** 事案とは「ある行為者 (または原因) による、
ある対象への、ひとまとまりの出来事」。

| 場合 | 扱い | 理由 |
|---|---|---|
| 同じ事案の別媒体・別言語の報道 | **同じ事象** | 同じ行為の別の報じ方 |
| 同じ事案の第 n 報 (初報 → 影響範囲 → 帰属 → 当局の警告 → 事後分析) | **同じ事象 (続報)** | 事案が同じ。新しい事実は版の差分と続報バッジで示す |
| 脆弱性の修正 (ベンダーの告知・パッチ) ⇔ その悪用・KEV への追加 | **別の事象。関係 (系統) で結ぶ** | 行為が違う (直した / 悪用した)。同じ CVE でも別の出来事 |
| 行政指導・当局の処分・業界団体の声明など、事案から派生した出来事 | **別の事象。関係で結ぶ** | 行為者が違う。元の事案の結果として起きた別の出来事 |
| 同じ行為者の別の作戦 | 別の事象 (関係: 同じアクター / キャンペーン) | 作戦が違う |
| 週次・日次のまとめ記事 | 別の事象 (関係: 包含) | 個別の事案ではない |
| 片方がまとめ記事・一括の勧告 (複数の事案・CVE の束) で、もう片方がその中の 1 件 | **まとめ (包含)**。行為が違っても (束が修正を載せ、もう片方が悪用を報じる等) 系統にしない | 2026-10-28 利用者判断。束の側は個別の事案ではないので、行為の比較 (問い 3) を当てない |
| 同じ書式の別の被害者 (流出サイトの一覧など) | 別の事象 | 被害者が違う |

### 見分ける問い (この順に)

0. 片方がまとめ記事・一括の勧告 (複数の事案・CVE の束) で、もう片方がその束に含まれる 1 件か。
   そうなら **まとめ (包含)** (問い 1〜4 より先に当てる。2026-10-28 利用者判断)。
   「束」= **別々の事案・別々の製品やベンダーを並べた記事** (週報・日報、複数ベンダーの KEV 追加、月例の更新の一覧など)。
   1 社の 1 回の告知・リリースに CVE が数件載るだけの記事や、1 つの事案に複数の脆弱性が絡む記事は束ではない (問い 1〜4 で判定する)。
   1 社の月例の更新 (Patch Tuesday など) のうち、別々の製品の修正を多数並べたものは束とする (2026-10-29、境目はまとめに揃える方針)。
1. 行為者 (または原因) と行為が同じ事案か。同じ → 2 へ。違う → 別の事象。
2. その記事は同じ事案の**続き**か (同じ事案の新しい局面・追加の事実)。続き → **同じ事象**。
3. 同じ識別子 (CVE・組織名) を持つのに行為が違うなら (直した / 悪用した)、**別の事象で系統の関係**。
4. 元の事案の結果として別の主体が動いたもの (指導・処分・声明) は、**別の事象で系統の関係**。

### 用途ごとに束ねる範囲

| 用途 | 束ねる範囲 | 備考 |
|---|---|---|
| 群化・統合 (事象を作る) | 同じ事象だけ | 統合の適合率 95% 以上を優先 (誤統合は読み手に別件が混ざる) |
| 関係 (画面の「関連」) | 系統 (修正 ⇔ 悪用 / 派生 / 包含) + 同じアクター | 回収は関係の表示でも補う |
| 続報バッジ・版の差分 | 同じ事象の中の新しい局面 | 事象の外の系統は関係の欄に出る |
| alert の重複 | 同じ事象 (続報を含む) | |
| 投稿直前の重複 (Discord) | 同じ事象のうち速さと決定論で判定できる部分集合 | 事象の根を参照する形が安全 (S2) |

### 目標との関係

群化の回収率の目標は 80% 以上 (docs/accuracy_targets.md)。統合の適合率 95% 以上を優先し、
定義上「別の事象」としたもの (修正 ⇔ 悪用・派生) の取りこぼしは**関係の表示で補う**。
つまり回収率は「同じ事象」の定義内で数える (系統の組を回収漏れに数えない)。

## 3. 設定の食い違い (compose / `.env` / コードの既定) — 2026-10-22 の棚卸し

flag は、compose を経由しない実行 (手元の `uv run`・replay スクリプト) で本番と違う挙動になる**。
