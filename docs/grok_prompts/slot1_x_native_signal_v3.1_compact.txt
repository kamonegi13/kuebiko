目的: 過去 24h の X 投稿で以下の領域 (A-F) のいずれかに該当するものを JSONL 収集。要約・翻訳・narrative・カテゴリ集計 一切なし。

# 収集対象 (A-F いずれか、各 0 件 OK)

A) Vendor 研究者の事前 teaser/初出言及。
公式: @MsftSecIntel, @Mandiant, @CrowdStrike, @TalosSecurity, @Volexity, @Wiz_io, @SophosLabs, @ESETresearch, @AhnLab_ASEC, @InsiktGroup, @TrendMicroRSRCH, @GroupIB_GIB
個人: @MalwareJake, @vxunderground, @bushidotoken, @SwiftOnSecurity, @jamieantisocial, @KostasTsale, @malwrhunterteam, @GossiTheDog, @InQuest
判定: 「blog post coming」「writeup soon」等の事前 teaser、または新規 actor/malware/TTP の初出言及。学者・コンサル blog 告知は除外。

B) リークサイト・extortion site の被害者掲載速報。
@FalconFeedsio / @RansomFeed / @DataBreaches / @ransom_db / @AlvieriD / @hackmanac / @RansomwareLive の "Group X listed Y as new victim" 投稿。
diversity: 1 author_handle 最大 6 件、7 件目以降は別 source 必ず探索。

C) 法執行アクション速報。
公式: @FBI, @Europol, @TheJusticeDept, @CISACyber, @CISAgov, @JPCERTCC, @nisc_forecast, @NPA_KOHO, @ICSCERT, @NCSC
explicit query (必ず実行):
英: "FBI announces seized", "FBI cybercrime indictment", "DOJ indictment cybercrime", "Europol operation takedown", "law enforcement seized infrastructure", "international cybercrime operation"
日: "JPCERT 注意喚起", "JPCERT-CC", "IPA 重要", "IPA 注意喚起", "警察庁 サイバー", "NISC 通知"

D) 被害組織関係者の自己開示。CISO/IT 部門責任者/中の人 が PR 前に X で「侵入された」「ランサム被害」を発信したと推測される投稿。ニュース報道の RT は含めない。

E) Scan/honeypot 異常観測。
@GreyNoiseIO, @Shadowserver, @badpackets, @SANSPenTest, @ISCHandlers, @TrustedSec の「新 exploit attempt 急増」「scan velocity スパイク」「mass exploitation observed」発信。

F) Active exploitation 確証 (以下の具体 event のみ):
- CISA KEV catalog への新 CVE 追加
- vendor advisory が "actively exploited in the wild"/"ITW" 明記
- PoC コードが GitHub/X で公開 (URL or screenshot 付き)
- 「mass exploitation observed」「exploitation imminent」と CTI 専門家が明記
単なる CVE 言及/一般論評は F ではない。

日本語 source 重視: theme C/D/F は必ず以下を探索。
handle: @JPCERTCC, @JapanIPA, @piyokango, @piedey
keyword: "JPCERT", "IPA", "NISC", "警察庁", "サイバー攻撃", "ランサム", "標的型", "情報流出", "不正アクセス"

# 量・出力ルール

- 上限 30 件、engagement.retweet+like 降順 truncate
- 件数下限なし、10 件未満でも質優先、無理に埋めない
- 24h 以内のみ、1 tweet を複数 record に分けない
- B diversity: 1 author_handle 最大 6 件
- engagement field 全 record で必ず取得記録 (filter は行わない、pipeline 側で処理)
- 同一事案の複数報道は両方含めて OK (異なる source からの同一事案も含める、pipeline で dedup)
- text 原文ママ、要約/翻訳/抜粋/注釈禁止
- media_urls/external_urls は実在 URL のみ、fabricate 禁止
- tweet を fabricate しない、実在 tweet のみ
- narrative/全体傾向/今日のまとめ/category 集計を出力したら違反 → 出力全体を `[]` に置換 (self-check)
- 監視 handle は参考、x_semantic_search で広く拾うことを優先

JSONL (1 行 1 record)。最初の文字 `{`、最後の文字 `}`。前後に説明文・見出しを出さない。
