## 1. 目的

1. **事象の重さ**と**こちらとの関連性** (日本・常設の問い / SIR・注視国) を別の値として持つ
2. **SIR / PIR を変えても、学習し直さずに追従できる**フローにする
3. 判定基準・正解集・教師データ・ML に**基準の版**を付け、変更の影響を見えるようにする

## 3. 設計原則

1. **事象の評価は平たく、学習する**: 深刻さは「何が起きたか」だけで決める。日本・SIR・特定国を理由に上げ下げしない。
   LLM の判定と学習の対象はこちらだけ
2. **関連性は決まりごと + 照合で、学習しない**: 日本・SIR・注視国との関連は entity (被害国・組織・関与国・
   アクターの国籍) と SIR の照合条件から導く。**文の語の正規表現で決めない** (P2)
3. **SIR / PIR はデータ**: 関連性の定義として DB で版管理する。triage にも教師データにも焼き込まない。
   変えたら照合を付け直すだけで、学習し直さない
4. **基準には版を付ける**: 判定基準の文 (深刻さの rubric)・正解集・教師・ML の記録に版を残し、変更時に
   影響件数を出す。版の合わないラベルは評価に使わない
5. **重要度は導出値**: 深刻さと関連性から決まりごとで導く (6 段階)。下流は必要に応じて元の 2 系統を直接見てよい
6. **Discord の配信は設計の制約にしない (2026-10-03 利用者方針)**: 配信は数ある下流の 1 つで、最後に合わせる。
   既存の配信ルール・チャンネル体系・旧 3 値との互換を保つために値の定義を曲げない。配信ルールは新しい値の上に
   作り直す (いまのルールを写像で移すことはしない)

## 4. 値の定義

### 4.1 深刻さ (severity) — 事象の評価 (v2: 記事の種類ごとに導く)
3 段階 (S3 重大 / S2 注意 / S1 参考)。**深刻度の軸だけからは導けない** (§7.1 の試算: 軸が軍事の記事にも被害を付けて
S3 にし、被害者のいない重大な脆弱性を S1 にした)。記事の種類 (category と event_kind) ごとに材料を変える:

| 記事の種類 | 材料 | S3 の例 |
|---|---|---|
| 事案 (侵害・ランサム・インシデント・APT の活動) | 深刻度の軸 (広がり・被害・確認・行為者・標的) | 確認済みの被害が組織横断以上 / 国家系が政府・重要インフラ・防衛を侵害 / 重要インフラの停止 |
| 脆弱性・勧告 | CVSS・KEV・悪用の有無・PoC・製品の普及 (境界機器・広く使われる基盤) | 実環境で悪用中、または CVSS 9 以上で広く使われる製品 |
| 脅威の分析・研究 | 新しい手口か・対象の範囲 (LLM 判定の欄を足す) | 新しい攻撃基盤・広範なキャンペーンの解明 |
| 政策・地政学・軍事 (サイバー以外) | **サイバーの深刻さの対象外** — 深刻さは付けず、関連性 (注視国・SIR) と別の欄「戦略上の重み」で扱う | — |
| まとめ記事・報告書・傾向 | 深刻さは付けない (中の個別の事象で扱う) | — |

- **記事の形の物差しは「新しい事実を伝えているか」(2026-10-03 利用者決定)**:
  - 年次・四半期の脅威報告・市場調査: 新しい事実 (新しいキャンペーン・手口・IOC・初めて明かされる事案) を
    含めば脅威の分析として深刻さを付ける。統計・傾向・既知の事案の集計・宣伝が中心なら派生記事
  - 軍事行動: 見出しや冒頭が直近の具体的な行動を報じていれば戦略上の重みは「重」(後半が論評でも)。
    行動が戦略・能力の分析の背景にとどまるなら「中」。週ごとの情勢まとめも新しい行動を報じていれば「重」
  - 政策・政府発表・勧告の中の攻撃: その記事が攻撃を初めて明らかにしているなら事象として深刻さを付ける。
    既報の攻撃を背景に引くだけなら政策の記事
  - いまの軸と記事の種類の欄では見分けられない → s23 で「新しい事実を報じているか」の欄を軸に足す。
    それまでは記事の種類 (論評・まとめ・入門 = 派生) で近似する
- **用語の定め (版 .5、2026-10-03 利用者承認・公的な枠組みと照合)**:
  | 点 | 定め | 照合した枠組み |
  |---|---|---|
  | 確認 | 被害者・当局に加え、独立した研究者が直接の証拠を持つ場合も確認済み。攻撃者の主張とその転載は「主張のみ」で、主張された件数・規模では重くしない | Admiralty コード (NATO AJP-2.1) の情報の確度「他の情報源で確認」。暴露サイトは水増し・架空の被害者の掲載が報告されている |
  | 代理勢力 | 記事が注視国の支援・指示を明示している勢力の行動はその国の行動。背景として触れるだけなら違う | 帰属は記事の書き方に従う (推測で国に結ばない) |
  | 重要インフラ | 電力・ガス・水道・通信・交通・医療・政府、金融は銀行・決済・清算・証券取引所・中央銀行。暗号資産取引所は含めず、被害額 1 億ドル以上の窃取を S3 | NIS2 は金額基準 (50 万ユーロ or 売上 5%) を組織の報告義務に使う。ニュースの「重大」はそれより桁の大きい事案に絞る |
  | 摘発・起訴 | 広く使われる犯罪基盤の解体・主要集団の中心人物の逮捕は S2、個人の小規模な逮捕は S1。摘発だけで S3 にしない | NCISS・NCSC はいずれも被害の影響で格付けし、摘発は対象外 |
  | 脆弱性 | 悪用の観測 (KEV) = S3、PoC の公開 = CVSS によらず S2、CVSS 9 以上 = S2 | SSVC (CISA/SEI) の悪用状況 none / public PoC / active。CVSS より悪用状況を先に見る |
  | 直近 | 記事の公開日から 7 日以内 | — |
- **採用 (2026-10-03 利用者承認、s23 で実装)**: NCSC の区分 (Category 1〜6) は**被害組織の規模** (大・中・小) と影響の重さで
  格付けし、「大規模組織への深刻な影響」を上から 3 番目 (Significant) に置く。いまの基準は単一組織の侵害を
  規模によらず S2 にしている。大規模組織の業務停止 (確認済み) を S3 にするには、被害組織の規模の欄が要る
  (s23 で軸に足す候補)。NCISS の「回復の見込み」「管理者の認証情報の窃取」も、いまの軸に無い観点
- **s23 で深刻度の軸に足す欄 (まとめ)**: ①新しい事実を伝えているか (派生記事の見分け) ②直近 (7 日以内) の
  具体的な行動を報じているか (戦略上の重みの重/中) ③被害組織の規模 (大・中・小、NCSC) ④回復の見込み
  (NCISS) ⑤管理者の認証情報の窃取 (NCISS)。あわせて軸は本文から付ける (要約だけだと正解率 69%)。
  教師は版 .5 の基準文で Opus が本文から付ける。決まりごとは欄が入ってから「大規模組織の業務停止
  (確認済み) = S3」等を足す
- **版 .7 (2026-10-03 夜、利用者承認): 規模は本文の件数で直す・境界の 4 型の線引き**
  - S3 の見逃しを母集団で推定した (決まりごとが S3 にしなかった無作為 200 件を Opus 5.5 で判定): 16%
    (95% 区間 9〜28%)。境界を除くとはっきりした見逃しは 2 件で、どちらも要約から付けた軸が本文の件数を
    落としていた。逆に規模を根拠にした S3 は 20 件中 14 件が誤りで、件数の無い記事に大きな規模を付けていた
  - 決まりごと: 本文の被害の文に書かれた件数 (人・記録・アカウント) で規模を上げも下げもする。件数が本文に
    無いのに 10 万件以上なら「不明」に戻す。攻撃者の主張だけの事案は大きな規模にしない。被害額も被害の文の
    金額だけを読む (売上・販売価格・身代金の要求額を拾っていた)。`corrected_axes` / `stated_victim_count`
  - 結果 (s21 の軸、測定用 250 件): 深刻さ 85% → 89%・S3 の適合率 71% → 77%・見逃し 5 → 6 件
    (増えた 1 件は誤った大きな規模で偶然 S3 だった例)。無作為 200 件: 見逃し 7 → 5、新たな誤った S3 は 0
  - 境界の型: **配布経路の汚染は S3** (正規の配布経路から悪性版。偽パッケージは S2)。いまの軸に欄が無いので、
    s23 で `distribution_compromise` を足す。**S2 のまま**: 犯罪系の配布キャンペーン (研究者が多数の侵害を
    観測していても)・被害の書かれていない国家系の手口の分析・漏えいの前に止まった複数組織への不正アクセス。
    S3 を広げないのは適合率が目標 (80%) に届いていないため。基準の文に明記し、教師の境界 S3 を付け直す
  - 付け直し (200 件、v2) 後の確定値: 見逃しの母集団推定 8% (区間 3〜20%、無作為 200 件中 3 件)。残りは
    軸の誤り 1・配布経路の汚染 1 (欄待ち)・境界 1。S3 の適合率は v2 の正解で 73% — 誤った S3 の主因は KEV と
    「確認された広範な被害」(どちらも 13 件、`data/mlx/s3_fp_basis.py`)
  - S3 の項目は S2 の項目より優先する (AI が使われた事例でも、国家系の政府への攻撃・広範な被害・大規模な漏えいなら S3)
    — 決まりごとは元からそう動く。基準の文に「上から順に見る」を明記した (教師のラベルの揺れを防ぐ)
  - 不採用: 「研究」の分類で被害が確認されたものを事案と同じ判定に回す案。v2 の正解で見逃しは不変 (0 件拾う)、
    誤った S3 が 4 件増えた (調査・ベンチマークに軸が「確認済みの被害」を付ける)。研究の上限 S2 は据え置き
    (`data/mlx/research_harm_eval.py`)。見逃しが出るとすれば分類の誤りなので、分類側で直す
- 軸は LLM が付ける (学習の対象)。**軸を付ける前に「サイバーの事象か」を判定する関門**を置く (軍事の記事に被害を付けない)
- 畳み方は設定 (表) で持ち、正解集で検証してから使う

### 4.2 関連性 (relevance) — こちらとの関係
複数の旗を持つ (1 つの値に畳まない):
| 旗 | 意味 | 導き方 |
|---|---|---|
| `jp` | 日本との関連: targeted (日本を狙った) / affected (日本の組織・利用者が被害) / mentioned (言及のみ) | 被害国・組織の辞書・関与国・本文の主語 (要約の後)。triage の時点は「落とさない保証」用の粗い判定のみ |
| `sir_ids` | 該当する SIR | SIR の照合条件 (match tree) と LLM 主題判定 (既存)。**取り込み記事の 77% が何かしらの SIR に該当する** (§7.1) ので、該当の有無だけでは関連性にならない。SIR に「関連性の重み」(高・中) を持たせ、高の SIR だけを関連性ありに数える |
| `nations` | 注視国 (中国・ロシア・北朝鮮・イラン) が行為主体か | アクターの国籍・関与国 |
| `questions` | 常設の問いの証拠条件に当たるか | 問いの証拠条件 (将来 SIR と結ぶ) |

### 4.3 重要度 6 段階 (導出)
深刻さ 3 段階 × 関連性 (あり / なし) で 6 段階。**並び (関連性ありの S2 と関連性なしの S3 のどちらを上にするか) は
利用者の判断 (§8)**。並びは画面の並べ替えと、1 つの値で絞る下流のためのもの (配信のチャンネルに合わせて決めない — 原則 6)。
**並びは案 A (深刻さを先に見る) に決定 (2026-10-04 利用者)**: 1 S3・関連あり > 2 S3・関連なし > 3 S2・関連あり >
4 S2・関連なし > 5 S1・関連あり > 6 S1・関連なし。理由: 関連性ありは記事の約 39% と広く、S3 は絞った判定。
関連性を先に置くと日本に関わるだけの注意級が世界で悪用中の脆弱性より上に来る。日本に関わるものだけを見る用途は
並びでなく「日本との関係」の絞り込みで満たす。深刻さの無い記事 (政策・地政学・派生) は 6 段階に入れない (戦略上の重みで扱う)。
旧 3 値 (high / medium / low) への写像は、移行期に配信以外の下流 (detect・深掘りの ML の列など) を壊さないためだけに持つ。

## 5. 新しいフロー

```
取得 → [段1 取り込みの判断] → 要約・抽出 (深刻度の軸・entity・関与国) → [段2 関連性の確定]
     → [段3 重要度 6 段階の導出] → 配信・ブリーフ・台帳・SIR 別要点・地図
```

| 段 | いま | 新しい形 |
|---|---|---|
| 段1 取り込みの判断 | LLM triage が SIR の記述を基準に 3 値。地政学は救済の段で補う | **LLM は平たい深刻さの見込みだけ** (SIR を読まない固定の rubric)。**取り込む = 深刻さの見込みが一定以上 OR 関連性の見込みあり** (日本の粗い判定・SIR の照合条件の軽量版を題と概要に当てる・注視国)。地政学の救済の段は関連性の見込みに吸収される |
| 要約・抽出 | 要約が重要度も出す (triage と二重) | 要約は事実と深刻度の軸・entity を出す。重要度は出さない (深刻さは軸から導く) |
| 段2 関連性の確定 | 日本は正規表現、SIR は照合 + LLM 判定 (事後) | entity から決まりごとで `jp` / `nations`、SIR は既存の照合 + LLM 判定。**正規表現の日本判定は廃止** |
| 段3 重要度 | LLM の 3 値 | 決まりごとの 6 段階 (表は設定で変更可) |
| 配信 (Discord) | 重要度 + 正規表現の旗 + カテゴリ等の複合条件 | **最後に作り直す** (原則 6)。いまのルールは移さず、新しい値 (深刻さ・関連性の旗・6 段階) の上で「何を即時に知らせるか」から決め直す (例: 即時通知 = S3 かつ (jp=targeted/affected または SIR の核))。チャンネルの数・分け方も見直してよい |
| 台帳 detect | importance と SIR 該当数を特徴量 | 深刻度の軸 + 関連性の旗を特徴量 (既に軸は入っている)。importance は外す |

### SIR / PIR を変えたとき
- 段1: 照合条件の軽量版を題に当てるだけなので、**保存した次の取り込みから効く**。LLM は SIR を読まないので学習に影響しない
- 段2: 既存の日次の付け直し (90 日窓) と LLM 主題判定の版 (pir_judge_rev) で追従
- 学習: 深刻さの rubric は SIR から独立 → **SIR を変えても学習し直さない**
- 評価: 正解集のうち関連性のもの (SIR 判定) だけを付け直す。深刻さの正解集はそのまま

## 6. 移行計画 (各段で検証してから次へ)

### 7.1 試算の結果 (2026-10-03、過去 30 日・取り込み 2,429 件、`data/mlx/simulate_severity_relevance.py`)
- いまの high 590 件: 軸からの深刻さで S3 456 / S2 91 / S1 43。いまの medium 1,839 件: S3 378 / S2 443 / S1 1,018
- 中身を読むと、ずれの多くは**軸の側の問題**: 軍事の記事 (部隊派遣・兵器工場の視察) に「破壊的・確認済み」が付いて S3、
  被害者のいない重大な脆弱性 (認証回避・重大な修正) が S1、年次報告に「確認済み・複数組織」が付いて S3 → §4.1 を v2 に改訂
- SIR の該当: 2,429 件中 1,862 件 (77%)。上位は「新しい PoC・業界注目の脆弱性」558・「重要インフラ」503 → §4.2 に重み
- 日本: 被害国または関与国が日本 413 件。注視国が関与 529 件

- **v2 の決まりごとで再試算** (記事の種類ごと・KEV と CVSS は既存のキャッシュ・関連性は高の SIR 14 本 + 日本 + 注視国):
  いまの high 590 → S3 359 / S2 151 / S1 19 / 対象外 (地政学) 61。いまの medium 1,839 → S3 199 / S2 504 / S1 601 / 対象外 535
  - high→S1 の 19 件と medium→S3 の 199 件を読むと、残るずれの原因は 3 つ:
    1. **記事の形式を見ていない**: 解説・逮捕・訴訟・年次報告にも「確認済みの被害」が付き S3 になる → 深刻さは事象を報じる記事にだけ付け、派生記事 (解説・法執行・報告) は元の事象から引き継ぐか参考扱い (`article_type` を関門に)
    2. **規模 (magnitude) を使っていない**: 100 万件を超える漏えいでも確認が「可能性」だと S1 → 規模の軸を S3 の材料に入れる
    3. **地政学の high 61 件は対象外になる**: データセンター・通信へのドローン攻撃など、サイバーの深刻さでは測れないが重い → §4.1 の「戦略上の重み」を別の欄として要る (判断点 §8)

  決まりごとの表は §4.1 を叩き台に、裁定済みの正解集 (Opus の週の上限が戻ってから) で調整する

### 8.1 推奨 (4・6)
