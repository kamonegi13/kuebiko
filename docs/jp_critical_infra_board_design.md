# 日本重要インフラ 脅威 posture board 設計

作成: 2026-07-08 / 状態: **実装済 (Phase A-D + v2 近接度ラダー §10)**。変更前に本書を読むこと。

現行の脅威可視化（観測源中心の世界地図）に対し、**対象中心**（subject = 日本の重要インフラ）で
脅威 posture を一枚に統合する I&W (Indications & Warnings) 型 board。棚卸しの結果、これが既存
可視化で埋まっていない**唯一の真の空白**だった（地図の sector フィルタ / National Situation(国別) /
PIR を手で横断していた）。

## 1. 統治原則（地図の統治原則を延長）

- **観測 ≠ 世界 / 暗域 = 不明 ≠ 安全**: 日本の CI 被害は開示が極端に少なく観測は特に疎・偏る。
  「静か = 安全」の誤読を board 全体で防ぐ（各分野に被覆信頼度と「静か≠安全」を明示）。
- **CI 脅威の本質は pre-positioning**（Volt Typhoon 型）: 可視の breach でなく事前潜伏。被害実績は
  氷山の一角。`socio_political_intent=prepositioning/disruption` を主役に。
- **精度の誠実性（可変精度）**: 各項目をその項目固有の解像度で表示。深さを一律に決めず、データが
  支える範囲でのみ深く、支えない所は「分野のみ」と明示（地図の country→city 精度バッジと同思想）。
- **較正・過大評価防止**: 潜在影響は憶測でなく evidence-linked + 確度ラベル（synthesis 信頼性原則）。

## 2. タクソノミ（二層）

- coarse `victim_sector`（現 21 canonical、global views 用）はそのまま。
- 派生 **`nisc_sector`（〜15 分野、board 専用）** を追加: 情報通信/電力/ガス/石油/水道/金融/クレジット/
  航空/空港/鉄道/物流/港湾/医療/化学/政府行政。coarse からの写像 + JP 項目はキーワード精緻化
  （energy→電力/ガス/石油、transportation→航空/空港/鉄道/物流/港湾 等）。**読み時導出 + mapping**
  であり新規抽出タグではない。global を割らないので非 JP 集計は fragment しない。

## 3. 4 系統の合成（MVP = 全部入り）

各 NISC 分野の posture を4系統から合成:
1. **観測イベント**: `victim_country=JP × nisc_sector`。疎だが実。
2. **潜在露出（脆弱性）**: `cve`/`kev`/`affected_product` × 「分野→典型技術」表。前方視・actionable。
3. **アクター標的傾向**: `top_sectors` に当分野を含み JP または同盟国を叩くアクター。
4. **同盟国リードアクロス**: 同一アクター/TTP が US/TW/KR で同分野を叩く → JP 同分野を elevated
   （`involved_country` + `actor.top_sectors/top_countries`）。**日本で観測される前に警告** = 予測方向。

## 4. actual / potential（名指しの境界）

- **観測（発生している）**: `victim_org` が抽出できた時のみ事業者を「事業者特定」精度で名指し
  （出典が明示した事実の中継 = OSINT。我々の推定で名前を足さない = アクター帰属の辞書ゲートと同規律）。
  抽出確度でゲート、低確度は「分野のみ（要確認）」。NISC 分野へは「主要 JP CI 事業者→分野」の小さな
  curated 表で配置。
- **潜在（発生しうる）**: 本質的に**露出クラス**（「製品 X を使う事業者」「OT 運用の電力事業者」）。
  **特定事業者名は付けない**。→ false precision を構造的に回避。
- 対称: **名指しは観測（事実中継）では正・潜在（我々の推定）では不可**。

## 5. 表示モデル（3 層ドリル + バッジ）

- **L1 分野 board（背骨）**: NISC 分野ごとに posture 要約（脅威度・傾向・被覆信頼度・「静か≠安全」）。
- **L2 項目**: 各項目を native 解像度で。`actual/potential` バッジ + 精度バッジ（分野のみ/事業者特定/
  システム特定）+ 確度。
- **L3 システム軸**（下記）。

単一国・対象中心のため**地図は不適**（国内 org 粒度 geocoding は却下済）。**分野を行とする board/matrix**
が正で、疎データを正直に扱える（空セル = ラベル付きで全分野表示）。

## 6. システム軸 `system_domain`

国家影響評価の最重要切り口。OT/IT の単純二値でなく**影響順 4 段**:
- **制御系/OT**（物理・供給に直結。最重要。pre-positioning / active manipulation を区別）
- **OT/IT 境界・監視系**（HMI/historian/リモート保守 = Purdue L3/3.5。多くの OT 事案の起点・
  pre-positioning の標的 = 分析的に最も旨みのある層）
- **情報系/IT**（業務・顧客データ・基幹系）
- **不明**（保守的既定。迷ったら OT にしない）

**本質は過大評価の減衰機構**: 電力会社の人事系ランサム ≠ 電力 OT 脅威。この軸が両者を分離し、
CI 事業者のただの IT 被害を国家 CI 脅威に水増しするのを防ぐ。

**derive-first**: まず既存信号から決定論導出（`ttp` の **T0xxx（ICS ATT&CK）** / `affected_product` が
ICS 製品 / OT-ICS-SCADA-制御系 キーワード / `malware_type`）。それで OT/IT/境界を分離できない時**のみ**
保存分類（`column/single/enum/summarizer_llm`）を追加。追加時は較正 + 保守的既定 + **tag_registry.yaml と
test_tag_registry の両更新**。

⚠ 却下済の「システムレベル挙動抽出」（process/file/registry + 動詞、AttacKG/EDR hunting 型）とは別物。
あれは細粒度の hunting 用抽出、こちらは粗い国家影響分類。混同しない。

## 7. データ・タグ（新規抽出タグは原則ゼロ）

規律（tag_registry の思想）= **読み時に決定論導出できるものは保存しない・検出の種類は curated・値は自由**。

| board の必要物 | 満たし方 | 新規タグ |
|---|---|---|
| nisc_sector | `victim_sector` + JP キーワード精緻化 | 不要（導出+mapping） |
| actual/potential | `category` + victim 有無 | 不要（導出） |
| ICS 判定 | `ttp` の T0xxx 名前空間 | 不要（導出） |
| 事業者名（観測） | `victim_org`（既存） | 不要 |
| 潜在露出 | `cve`/`kev`/`affected_product`（既存）× 分野→典型技術表 | 不要（既存+lookup） |
| 意図 | `socio_political_intent`（既存） | 不要 |
| 事業者→分野 | 主要 JP CI 事業者 curated 表 | lookup（タグでない） |
| system_domain | 上記導出 → 不足時のみ保存 | 唯一の候補（derive-first） |

**ついでに閉じる gap**: `ttp` の ATT&CK catalog 未照合（registry line 39 の自認 gap）を照合するように
enrichment（新 type でなく正規化 seam 強化）→ ICS/Enterprise・戦術の決定論導出が board 以外にも波及。

**新規 curated lookup 表 2 枚**（config、タグではない・資産インベントリではない）:
- 「NISC 分野 → 典型製品/ベンダ」（潜在露出とシステム軸(潜在)を給電、二役）
- 「主要 JP CI 事業者 → NISC 分野」（観測事案の分野配置）

## 8. 却下・スコープ外（再提案しない）

- **JP CI 事業者の資産インベントリ（OSINT 含む）を作らない**: (a) Shodan 等は露出 IT 面のみで内部 OT は
  原理的に不可視（資産レベルの「暗域≠安全」）、事業者帰属も誤りやすい。(b) より重要な理由 = この種の
  ツールが「どの JP CI 事業者がどの脆弱製品を運用するか」の DB を作成・保持すること自体が**攻撃者の標的
  パッケージそのもの**であり負債。能動 recon への mode 転換でもある。代替 = 分野×典型技術プロファイル
  （事業者単位でない）+ 公表 OSINT の受動取込。
- **地図フォームでの JP CI 表示**（国内 org 粒度 geocoding が必要 = 既に却下）。board/matrix が正。
- **impact（流出データ種別/規模）タグ**: registry の既知 gap（P4 第2弾候補）。severity を厚くするなら後で
  足すが MVP ブロッカーではない。

## 9. 実装フェーズ（提案・全て full MVP へ向かう構築順）

- **A. 基盤**: 二層タクソノミ（`nisc_sector` mapping + JP キーワード精緻化）、curated 表 2 枚、
  `ttp` catalog 照合の gap 閉じ + T0xxx→ICS 導出。
- **B. board backend**: 4 系統集約 API（分野×posture）、system_domain の derive-first 導出、被覆信頼度算出。
- **C. frontend board**: L1 分野 board + L2 項目（actual/potential + 精度/確度バッジ）+ L3 システム軸。
- **D. 同盟リードアクロス + 仕上げ**: read-across 注入、「静か≠安全」明示、疎データ全分野表示の詰め。

## 10. 表示モデル v2: 近接度ラダー（2026-07-09 再設計）

初版（カード＋4系統の記事リスト）は本番実データで**評価にならない**ことが判明し再設計:
high 8/16 分野で飽和（1 件の high 記事で分野が high）、漏えいデータ種別（「クレジットカード
情報」）による被害者分野の取り違え（仏壇店→クレジット分野等）、誤送信/紛失の非敵対事象が
脅威計上（政府・行政の大半）、KDDI 1 事案が 28 項目（報道クラスタ未集約）、`ics`⊂`forensics`
部分一致の system_domain 誤爆。

### 中核: 近接度ラダー（posture = 脅威がどの段階まで来ているか）

```
静穏 quiet → 予兆 indication → 標的化 targeting → 侵害(IT系) intrusion_it → 制御系接近 ot_approach
```

- **制御系接近**: JP 当分野の敵対事象 × (OT|境界) or `intent=prepositioning`（Volt Typhoon 型は
  IT 経由でも最上段）。
- **侵害(IT系)**: JP 当分野の敵対事象（IT/不明）。**system_domain が減衰機構としてレベルに構造的に
  参加**（§6 の設計意図がここで効く）。
- **標的化**: アクターが日本の当分野を標的 / KEV×分野典型技術（実悪用中の経路が開いている）。
- **予兆**: 同盟国同分野の read-across / アクター分野関心 / 非 KEV 分野技術脆弱性。
- 分野の到達段階 = 空でない最上位バケット。決定論・飽和しない。

L1 = **分野×段階マトリクス**（§5 の「board/matrix が正」への回帰）: 行=16 分野固定順
（グループ: エネルギー・ライフライン/情報通信/金融・決済/交通・物流/医療・化学/政府・防衛、
空間記憶で変化が目に飛び込む）、列=4 段階（左→右にエスカレーション）、行末=到達段階バッジ+
Δ+被覆。分野ごとに決定論合成の一行 headline。行クリック→段階別詳細（近い順）。

### ノイズゲート（board の信頼性の土台）

1. **敵対性ゲート**（`ci_posture.is_nonthreat_mishap`）: 誤送信/紛失/置き忘れ/設定ミス等 =
   アクター不在の事務事故は脅威計上せず `nonthreat` 件数として別掲（正直さ維持）。
2. **canonical ゲート**（`nisc_sectors`）: 非 CI canonical（retail/media/education 等）は text に
   何が書かれても対象外。text 精緻化は canonical の許容先内のみ（financial→金融系のみ等）
   — **被害者の分野 ≠ 漏えいデータの種別**。credit キーワードは事業者語のみ、
   `銀行(?!口座)`/`bank(?! account)`/`行政(?!処分)` ガード。
3. **報道クラスタ集約**（`ci_posture.merge_observed_events`）: victim_org（正規化）の連結成分で
   同一事案の多重報道を 1 事象に（KDDI 型 28 報道→1 事象、`report_count` に保存）。org 無しは
   title 完全一致のみ（過剰連結しない保守側）。証拠は合併（domain/確度は最大側）。
4. **潜在露出は製品→分野リンクのみ**: text fallback 廃止（汎用 KEV 告知が政府・行政に落ちる
   誤配置の根治）。
5. **phishing category を観測から除外**: ブランド詐称は顧客標的であり事業者システム侵入でない。
6. **system_domain 較正**: 境界一致（`kw_hit`）で `ics`⊂forensics 誤爆根治。boundary は
   強キーワード（HMI/historian 等）単独可、弱キーワード（リモート保守/踏み台）は OT 文脈共起
   必須。bare「境界」「remote access」廃止。

### 変化検知（I&W の核心）

同長の前窓で観測/潜在を再計算し、段階の昇降（Δ）を分野行と「前期間からの変化」ストリップに
表示。アクター標的傾向は snapshot 由来の遅い信号のため窓間比較の対象外（両窓に同じ床）。
全期間表示では Δ なし。

## 11. 事業者 3 層ゲート（2026-07-09 v2.1）

v2 稼働後も観測レーンに非 CI 事業者（fintech SaaS/商社/ポイントサービス/クラウド PBX）が
約 1/3 混入していたため、**victim_org（抽出済み被害主体）に対する 3 層判定**を導入:

- **層1 指定事業者名簿**（`src/cti/ci_operator_roster.py` + `ci_operators_builtin.py` 約160社）:
  事業者名→分野のみの公知情報名簿。**DB (config_store key `jp_ci_operators`) が SSoT**、
  BUILTIN はコード所有の seed + fail-safe（channel_registry/model_tiers と同パターン）。
  UI 編集 = `/app/jpci/operators`、版履歴/revert = config-history。別名（和名/英名/略称/
  主要子会社）を同一 id に解決 → **報道クラスタ merge の鍵**（アフラック和名/英名 8 報道→1 事象）。
  ⚠ 統治境界: 名簿に技術・製品・露出情報の列を**将来も足さない**（§8 資産インベントリ禁止は
  事業者→資産のマッピングの話。名前→分野の名簿は抵触しない）。短い 2 文字 CJK ブランド略称
  （東急/近鉄等）は誤爆するため入れない（length-aware 教訓）。
- **層2 事業者型判定**: 種別サフィックス/固有語の決定論パターン（〜病院/〜市/〜銀行/信組/
  自衛隊/〜電力/水道局/検察庁 等）。全列挙不能な中小 CI 事業者（半田病院型の実被害）を回収。
  防衛→水道→医療→…→政府の順で具体が汎用に勝つ（航空自衛隊→防衛）。
- **層3 周辺観測 (peripheral)**: org 特定済みで両層に非該当 = 非 CI 確定 → 段階を駆動しない
  折りたたみレーンに降格（完全に消さない = ゲートの見落とし監査可能）。
  org 抽出の無い記事は検証不能のため canonical ゲートを信頼して段階に残す（recall）。ただし
  **周辺 org の中核名（HD/株式会社除去、4 文字以上）が title に現れる org 無し記事は道連れ降格**
  （同一事案の org 抽出揺らぎで CI レーンに漏れない）。

付随ゲート: ブランド詐称（「〜を装った」ボイスフィッシング等 = 顧客標的）は侵害の実示唆が
併記されない限り観測対象外。回顧・インタビュー記事（「被害企業が語った」）は調査記事ゲートへ追加。

事象 payload に `operator_tier` (designated/type/null)、分野に `peripheral[]` + counts。
指定事業者は名簿 canonical で表示（表記ゆれ統一）。

### 公的指定リストとの突合（2026-07-09、v2.2）

「NCO の指定する重要インフラ事業者は網羅されているか」への対応。公的指定の階層:
- **NCO（国家サイバー統括室、2025-07 に NISC を改組）重要インフラ行動計画** = **15 分野**の指定
  （事業者は分野ごとの業法カテゴリ定義で、統一の公表名簿は無い）。
- **経済安全保障推進法の特定社会基盤事業者**（基幹インフラ制度）= **社名単位の唯一の公的指定**
  （内閣府 統合一覧 `infra_jigyousya.pdf`、令和8年7月1日現在 257 者）。
- **サイバー対処能力強化法（2025）の基幹インフラ事業者** = 特定社会基盤事業者ベース。

**突合結果**: 内閣府統合一覧（機械抽出 245 名義）に対し **層1 名簿 233 / 層2 型 11 / 不一致 1→0**。
BUILTIN 名簿を 167→**304 社**に拡充（発電 IPP・送電 19 / 港湾運送 28 / 地銀・系統中央・
市場インフラ 33 / 放送 6 = NISC 情報通信分野の一部として it_telecom / 水道 19 / LPG 元売 等）。
- **意図的除外 1**: 全国農業協同組合連合会（LPG 輸入役務で指定だが主機能は農業流通 —
  石油分野への配置は誤誘導。型判定 農業協同組合→finance が JA バンク文脈で受ける）。
- **複合事業者の扱い**: 指定役務に従い収載（日本製鉄 = 発電事業 50 万 kW+ 指定 → electricity。
  三菱重工は発電指定もあるが防衛プライムとして defense を維持 = 1 社 1 分野の制約下の主レンズ判断。
  UI で分野変更可）。
- **名簿は指定リストの上位集合**: 指定外でも NISC 分野の系統重要事業者（大手私鉄・JR四国/貨物・
  羽田ターミナル・ISP・医療グループ・防衛産業・省庁）は維持。防衛は NCO 15 分野外の独自分野。
- **技術的教訓**: 官報・公的文書は全角英数・全角記号（ＮＴＴ、ニッケル．エンド．ライオンス）—
  org 照合は**両側 NFKC 正規化**が必須。多数 victim の SaaS 侵害では判定に使った org を
  operators 先頭に置く（merge cap / DB 値ソート順で判定根拠が欠落しない）。
- 更新運用: 内閣府一覧の改訂履歴（PDF 末尾）を四半期程度で確認し名簿 UI から反映。

### NCO 15分野クラス定義との突合と収載ドクトリン（2026-07-09、v2.3）

「NCO 15分野の細部条件から企業を列挙できないか」への対応。NCO 行動計画 別紙1
（対象となる重要インフラ事業者等）は各分野を**クラスで定義**する（電力=「一般送配電事業者、
主要な発電事業者」、医療=「医療機関（小規模を除く）」等）。全分野に「**主要な**」という
限定詞が付いており、経済安保の数値基準（シェア5割超カバー等）がその公式の操作化。

**収載の本質**: 名簿は業界名鑑ではなく「**この事業者の侵害は国家機能の維持に直結するか**」の
判定器。名簿を拡げるほど stage3「侵害」が賑わい、v2 で回復した「稀=意味を持つ」較正が薄まる
→ **拡大は recall と較正のトレードオフ**。収載の線引き = 経済安保数値基準（=公式の「主要な」）
＋ **防衛 CTI 固有の増幅軸**（下記）で引く。全数列挙が要るクラス（自治体/病院/水道/届出通信
2万）は**型判定がクラス定義の完全実装**なので名簿に列挙しない。

**CTI 固有の増幅軸（NCO 突合では出てこない、本ツール目的固有）**:
- **攻撃インフラ化**: ISP は被害者かつ pre-positioning の hop（Volt Typhoon 型）→ 主要 ISP を
  実勢シェアで限定収載（登録2万全部ではない）。
- **集中ノード（気づきB）**: 清算・決済・取引の単一障害点は「代替可能な大手」とカテゴリカルに
  異なる（1つの侵害が分野横断カスケード）。`SYSTEMIC_NODE_IDS`（コード所有・10者: 全銀ネット/
  JSCC/ほふり/JASDEC/JPX/TFX/全銀電子債権/CARDNET/カストディ銀/JPRS）で board に「基幹ノード」
  バッジ。公知の構造知識であり資産インベントリではない。
- **DIB（防衛産業基盤、気づきC）**: NCO 15分野**外**（本ツールは独自に「防衛」分野を持つ）。
  中朝アクターが実際に狙った層。防衛専業/準専業を収載（新明和/豊和/細谷火工/日本工機/三菱
  プレシジョン/明星電気/パスコ/日本アビオニクス/多摩川精機）。**多角化巨大企業（日立/東芝/
  ダイキン）は defense に force-route しない** — 民生侵害の誤流入 = 過剰帰属再発を防ぐ。ただし
  三菱電機/NEC/富士通は防衛電子 3 プライムかつ 2020 実標的のため DIB identity 顕著として維持。
- **影響工作**: 地方放送局は停波・乗っ取り観点。型判定（放送$/テレビ$、放送大学は末尾一致で
  誤爆回避）で構造被覆。

**気づきA = 暗域の定量化（最大の表現改善）**: 権威ある名簿ができた今、「静か≠安全」を
定量化できる。board は分野ごとに `designated_total`（指定 M 事業者）と `designated_observed`
（窓内で観測された distinct 指定事業者 K）を返し、UI に「指定 M / 観測 K」を表示 → **暗域が
可視化・定量化**される（I&W フレーム。名簿作業が初めて可能にした）。observation = 報道された
事案であり監視ではない／absence = 開示希少であり安全でない、を凡例で明示。

**収載しない（確定）**: 中堅クレカイシュア（中堅1社の顧客データ漏えいは決済機能の国家影響でない）／
自治体・病院・水道の全数列挙（型 = クラス定義の完全実装）／届出通信2万。**名簿 ~400社上限目安**で
レビュー可能性を維持（超える網羅要求は名簿でなく registry 自動取込という別設計の話）。

**記録した実装外の観測**: クラウド/SaaS 横断脅威（める配くん型 = NCO 格子に乗らない新種、
将来「横断脅威レーン」独立設計）／反復被害シグナル（同一事業者の窓内2回）は別機能。

名簿 323社（v3）。event payload に `systemic`/`operator_id`、分野に `systemic_hit`/
`designated_total`/`designated_observed`。技術教訓: 官報の全角英数・記号は両側 NFKC 必須。

## 12. 行動中心レーン: 世界の国家アクター行動（2026-07-10、v3）

### 棚卸しで確認した根本問題（実データ、90日）
board は victim 中心（JP 事業者が侵害され報道された事案を待つ）。だが実データでは、国家
アクターの行動信号はほぼ全て**非 JP コーパス**に存在し、victim 中心では構造的に不可視:
コーパス16,515件中 JP victim は441件（2.7%）。**prepositioning 70件中 JP victim 0件** /
espionage 303件中11件 / disruption 363件中2件。エッジ機器言及170件。Volt Typhoon 等の
国家アクターは各20-360件で存在するが大半が非 JP。

### 中核: 行動中心レーン（doctrine × コーパス集約）
mission の最上位 = 国家アクターの行動（情報摂取・事前潜伏）の可視化。個々の JP 事案は疎でも、
大量ニュースの集約で分野への脅威姿勢が浮かぶ。実装:

- **doctrine = 静的な標的プロファイル**（`src/cti/threat_actor_doctrine.py`、`STATE_ACTOR_SECTORS`）:
  国家アクター → 標的 NISC 分野を**公的勧告に接地**して code 所有（Volt Typhoon = CISA
  AA24-038A の 通信/電力/水道/交通 等）。観測 top_sectors が疎になる理由（アクターは victim を
  名指さず活動）を doctrine が補完。攻撃者の標的傾向の公知知識であり資産インベントリではない。
- **コーパス集約 = 動的な活動性**: threat_operations snapshot（既存、追加 query なし）から
  actor の nation / top_intents（事前潜伏/諜報/破壊）/ total_articles / spike / is_new / ICS-TTP。
- 両者の積を分野ごとの `threat_behavior` として射影。`is_state_nation`（中朝露イラン）で敵性
  国家に限定、`dominant_strategic_intent` で金融犯罪 intent を除外・事前潜伏を最優先。

### 二面併記（静穏の再定義）
各分野行に **JP 観測段階（近接度ラダー）** と **世界の国家アクター行動** を並列表示。ラダー
（JP 近接度）は不変 — 世界行動を段階に折り込むと全分野が予兆に平坦化するため、独立レンズと
する。分野が真に無信号なのは JP 観測静穏 **かつ** 世界行動も無い時のみ（`world_active`）。

### 横断キャンペーン合成（集約が個を超える創発信号）
同一国家アクターが 3+ 分野で事前潜伏/破壊 intent × 活発（total_articles≥3）→ `campaigns` に
「協調的インフラ作戦の兆候」として board 頭部に提示。相関のみ（因果は主張しない・報道時刻≠
実発生、cyber_geopolitical_correlation の原則）。

### 防衛/DIB 名簿拡充（36社）
JMU（護衛艦・潜水艦）ほか造船（三井E&S/カナデビア）、防衛電子は**子会社名で収載**（東芝
インフラシステムズ/日立国際電気 — 親の民生侵害を defense に誤流入させない = 過剰帰属回避）、
OKI/JRC/古野/東京計器/日油/住友重機/石川製作所/IHIエアロスペース/防衛研究所 等。

payload: 分野に `threat_behavior[]`/`world_active`/`counts.behavior`、board に `campaigns[]`/
`intent_labels`。doctrine は公的勧告更新時に code で拡充（~25 アクター）。
