# ニュースの絞り込みの整理 (2026-10-04 案)

対象: ニュース検索 (`/app/news`)・事象ニュース (`/app/eventnews`)・ダッシュボードの記事フィード / 事象ニュースの部品。運用画面と写しで共通。

## 1. いまの問題
- 絞り込みが横に 11〜12 個並ぶ (検索語・カテゴリ・サイト・日本との関係・チャンネル・深刻さ・関連性・政策地政学・本文・意図・SIR・アクター・ベンダ・期間・並び)。どれが主でどれが補助か分からない
- 「関連性」と「日本との関係」が別の選択で、組み合わせると意味が重なる (日本が標的・被害は必ず関連性あり)
- ダッシュボードの部品は同じ項目を 1 つずつ設定する。画面と部品で項目がずれる (事象ニュースの部品は 3 項目だけだった)
- 画面と部品で同じ「見方」を 2 回作る必要がある

## 2. 方針
1. **常に出すのは 4 つ + 並び**: 検索語 / 重要度 / 関係 / 期間 / 並び (新しい順・重要度順)
2. **残りは「詳細な絞り込み」に畳む**: カテゴリ・サイト・意図・SIR・アクター・影響ベンダ/製品・本文の有無・政策地政学を含める・(事象のみ) 複数媒体/統合済み/新事実あり・(運用のみ) チャンネル。畳んでいても、選んだ条件は下のチップで見える
3. **選んでいる条件をチップで並べる** (× で外す・「すべて解除」)。畳んだ詳細の条件もここに出る
4. **「関連性」と「日本との関係」を 1 つの「関係」にまとめる**: すべて / 関連性あり / 日本が標的・被害 / 日本に触れるもの。日本が標的・被害は関連性ありの一部なので、別々に選ばせると意味のない組み合わせができる
5. **ビュー (名前付きの絞り込みの組) を画面の上にタブで出す**。ダッシュボードの部品は**ビューを選ぶだけ** (+ 件数・表示の形)。部品のタイトルはビュー名、見出しのリンクはそのビューの画面
6. **絞り込みの部品は 1 つ** (ニュース検索と事象ニュースで共通。事象だけの切り替えは詳細に足すだけ)

## 3. 既定のビュー (案)
| ビュー | 条件 |
|---|---|
| 注目 | 重要度 注意以上・関係 関連性あり |
| 日本 | 関係 日本が標的・被害 |
| 重大 | 重要度 重大のみ |
| 脆弱性 | カテゴリ 脆弱性・重要度 注意以上 |
| 国家系 | 関係 関連性あり・カテゴリ APT |
| 地政学 | カテゴリ 政策・地政学 (政策地政学を含める) |
| 注意以上 | 重要度 注意以上 (関係・カテゴリ等は絞らない)。ダッシュボードの事象ニュース部品の既定 |
| すべて | 条件なし。ダッシュボードの記事フィード部品の既定 |

利用者は「いまの絞り込みをビューとして保存」で足せる。保存先は運用画面 = DB (版履歴あり)、写し = その端末の localStorage。

## 4. 進め方
1. 共通の絞り込みの部品 (常時 4 つ + 詳細 + チップ、関係の統合) を両画面に入れる。URL の形と API は変えない (保存済みのリンクが壊れない)
2. ビュー (既定 8 つ + 保存) を足す
3. ダッシュボードの部品の設定を「ビュー + 件数 + 表示の形」にする。いまの部品の設定は「その条件のビュー」に読み替える
