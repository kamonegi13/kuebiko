# replay の事前登録 (prereg)

本番の出力を変える変更を、過去の記録を再生 (replay) して比べるときの事前登録の型と置き場。
各 replay の判定の項目 (計画台帳の `stats.prereg`) はこのディレクトリの `<名前>.md` を指す。

**原則: 結果を見る前に、仮説・母集団・標本・合否の線を固定し、別のコミットで残す。**
prereg のコミットは、対応する replay の実行より前でなければならない
(判定の項目の `prereg_commit_by` までに、コード・結果とは別のコミットで)。

## prereg の型 (1 replay = 1 ファイル。以下の見出しを必ず埋める)

1. **仮説**: 何が良くなる (または悪くならない) か。1〜2 文。向きと指標を書く。
2. **母集団**: 対象の行の定義 (表・絞り込み・除外)。除外した行の数と理由を数える欄を作る。
3. **期間と事象時刻の分割**: 窓は**事象時刻**で切る
   (`src/storage/event_time.py` の `EVENT_TS_EXPR` = 公開時刻・取込で上限・欠損は取込時刻)。
   DB へ書いた時刻 (entity の `created_at` 等) で切らない。学習・調整に使った期間と
   判定の期間を事象時刻で分け、境界の日付を書く。
4. **標本と重み**: 全件か抽出か。抽出なら層・各層の件数・抽出の乱数種・重み
   (層の母集団比で重み付けする場合は式)。層ごとの n が小さいときは区間を併記する。
5. **対の検定**: 同じ入力に両腕を当てる (対にする)。検定の名前 (例: 符号検定・McNemar・
   ブートストラップ区間)、有意水準または区間の幅、多重比較の扱いを固定する。
6. **合否の線**: 数値で書く (例: 「適合率の差の下側 95% 区間 > 0 かつ回収率の低下 ≤ 2pt」)。
   **結果を見る前に固定する。**
7. **汚染の鍵 (R18)**: 次節。
8. **判定集の同一性**: 次節。
9. **変更履歴**: 線・母集団・標本を変えたときの記録 (後述の変更規則)。

## 汚染の鍵 R18

学習・調整に使った記事と、判定の標本が同じ出来事で繋がっていると、独立でなくなる。
判定の標本の各行について、次の**和集合の閉包**に学習・調整側の行が入っていれば汚染として外す
(外した数は報告に必ず書く)。

- 最新の事象の根 (`merged_into` を辿った根) が同じ記事
- CVE を共有する記事、または被害組織 (正規化後) を共有する記事
- 要約埋込のコサイン類似度が 0.80 以上の記事

3 つを辺として連結成分を作り、成分ごとに学習側・判定側のどちらかへ寄せる
(成分を割らない)。閉包の計算に使った版 (スナップショット・コード) を manifest に残す。

## 判定集の同一性

判定集は **ファイルのパスと sha256** で同一視する。id の別名で同じ集合を別物に見せない。
prereg に、判定集ごとに `path`・`sha256`・行数・作成者 (作る項目の id) を書く。
学習・調整に使った集合と path か sha256 が同じなら、判定集にしてはならない。

## 判定集にしてはならない正解集 (tainted)

学習または調整に使った集合は、判定に使わない (方針は strict: 分割の例外も認めない)。
現在の一覧の SSoT は計画台帳の `gold_sets` (`tainted: true`)。主なもの:

- 群化 (pair) の学習用の標本 3 本 (`eval_sample*.json`)
- detect の正解集 (`detect_goldset.jsonl`、全件学習に使用)
- 台帳の割当・深刻さ C (s3) の学習集合
- 統合のハブ・月次の関門の調整に使った 80 組
- 関与国の規則 3 の調整に使った 150 件
- 深刻さの正解 v4・v5_final (importance_v2 の調整・s3 の学習)
- 薄い本文 R3 (閾値の選定)・triage の境界・平たい triage 150 (合否の調整)
- SIR 別の要点の関門の閾値に使った 300 文
- 種別 (event_kind) の旧正解 455 (候補の絞り込みに使用。判定は新しく作る集合で行う)
- 被害国の補完の Opus 裁定 69 件 (47 件は既存ラベルと一致した発火で独立でない。独立は 22 件)
- Grok リンクの関門の語の選定に使った 44 投稿

台帳の側で `tainted: false` になっている集合だけが判定集の候補。台帳の更新が遅れていないか、
使う直前に学習・調整のコード (`scripts/` `data/` のビルド) を grep して確かめる。

## replay の manifest に prereg の sha を残す

replay の出力ディレクトリの manifest に次を必ず書く。

- `prereg_path`: 本ディレクトリ内の prereg のパス
- `prereg_git_sha`: prereg を最後に変更したコミットの sha (`git log -1 --format=%H -- <path>`)
- `prereg_blob_sha256`: 実行時点の prereg ファイルの sha256
- 実行時の HEAD の sha、判定集の `path` と `sha256`、R18 の閉包の版

実行前に、`prereg_git_sha` が実行のコミットの祖先であることを確かめる
(`git merge-base --is-ancestor`)。祖先でなければ、prereg が後出しなので実行しない。

## 線を変えてよいとき

結果を見た後は、合否の線・母集団・標本・検定を**変えない**。変えざるを得ないときは次を守る。

- 変更履歴の欄に、日付・変えた項目・変更前後・**理由**・結果を見た後であること、を記録する
- 変えた後の結果は「探索的」と明記し、合否の判定には使わない
  (判定したい場合は新しい標本で prereg からやり直す)
- 理由の無い変更、結果に合わせた変更は認めない

## 置くもの・置かないもの

- 置く: 判定の設計、数値の線、手順。
- 置かない: 記事の本文、実在のドメイン・組織名・実際のインシデントの詳細、個人の情報。
  例は `kuebiko.example` や架空名にする。
