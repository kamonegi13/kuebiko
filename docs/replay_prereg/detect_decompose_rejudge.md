- **題名**: 区間の開始時刻以前の最新 revision の claim (`latest_revision_before`)。claim が空なら今の題名

## 4. 標本と重み

- 窓の抽出 (元の prereg と同じ): 適格な区間を開始時刻の昇順 → `random.Random(20261105)` で shuffle → 先頭から 20 窓、
  同じ UTC 日からは最大 3 窓。**乱数種は前回 (20261104) と変える** (前回と別の標本であることを種でも分ける)。
  適格な窓が 20 未満ならあるだけ使い、18 未満なら判定不能。**閉包の汚染 (§7) で窓を選び直さない**
- 各窓 × 各腕を 3 回。腕の順序は `random.Random(20261105 + 窓の通し番号 * 10 + run)`
- 重み: 各窓は等しい。層 = UTC 日 (参考のみ)
- 単位・抽出・2 回目の裁定は **336a9b27 で固定した方法をそのまま踏襲**する (乱数種だけ 20261105):
  - 畳んだ単位の鍵 = (窓, 記事 id の集合, claim 文)。腕は単位の属性 (開いた腕の集合)。層 = 両腕 / 現行腕だけ / 出荷腕だけ
  - R18 (§7) で外す単位は**抽出の前**に U から除く
  - 残りの U > 260 なら、単位 id (鍵の sha256 先頭 16 桁) の昇順 → `Random(20261105)` で 1 回 shuffle → 層ごとに最大剰余法で
    比例配分した数を shuffle 順の先頭から取る。重み = 層の U / 抽出数。抜かれなかった単位は同じ層の裁定できた単位の割合で補う。U ≤ 260 なら全数
  - 2 回目の裁定: 抽出した単位から `Random(20261105)` で 40 単位 (単位 id の昇順から sample)、1 回目と別の rubric 名で独立に。
    一致率・κ の報告専用
  - 単位の判定の合成: Q1〜Q3 に 1 つでも「いいえ」→ 誤り。「いいえ」が無く 1 つでも判断不能 → 判断不能 (単位の外)。3 つとも「はい」→ 正しい
  - 「裁定できた単位が 80% 未満」は抽出した単位のうちの割合で読む

## 6. 合否の線 (元の prereg と同じ値。すべて満たして合格)

- **P1 (主、非劣性)**: d_w の平均の bootstrap 95% 区間の下限 ≥ −0.5 (窓あたり)。かつ Wilcoxon が「出荷腕が有意に悪い」
  (p < 0.05 かつ d_w の中央値 < 0) でない
- **P2 (誤開設率)**: 誤開設率の差 (出荷 − 現行) の bootstrap 95% 区間の上限 ≤ +5 点
- **P3 (関門の止めすぎの歯止め)**: 出荷腕の全 run の「固有名詞の裏付けの関門で止めた claim (`n_gate_blocked`)」/「開いた claim + 止めた claim」 ≤ 0.20。
  分母 30 未満は判定不能。**分子は元の prereg と同じ裏付けの関門だけ**。書き手の直しで止めた claim (忠実さの違反) と塊
  (単発の事案) は別に数えて参考に出す (判定に使わない)。書き手の直しが正しい開設を止めすぎる害は P1 (C の減少) に表れる
- **P4 (出荷腕の健全性)**: 分けた形が適用された (窓, run) の割合 ≥ 90%。下回れば判定不能
- **P5 (開設数の歯止め)**: 出荷腕の開設数 (畳む前) の合計 / 現行腕 ≤ 1.5
- **判定不能の条件**: 窓が 18 未満 / P3 の分母 30 未満 / P4 が 90% 未満 / 裁定できた単位が抽出の 80% 未満 /
  **閉包の段 (§7.2) がどれも最大成分 < 0.30 を満たさない** / **R18 で除いた単位が U の 50% を超える** (残りが窓の標本を代表しない) / 実行の前提 (§9) を満たさない。
  判定不能は合格ではない。SW-DETECT は出さず調整役へ戻す
- 1 つでも不合格なら不合格。本書の中で線・母集団を変えて再判定しない

### 7.2 閉包の直し (結果を見る前に固定)

前回の閉包 (R18.1) は最大成分が 30.8% で上限 0.30 を超え、除外 154 単位のうち 96 が最大成分経由だった。長く続く事案の
事象の根・頻出の CVE・頻出の被害組織が「ハブ」になり、無関係な記事まで 1 つの成分に繋いだと読む。そこで、**ハブの値を鍵にしない**
段を、弱い方から順に決めておき、最初に最大成分 **< 0.30** を満たした段を使う (R18.2)。

| 段 | 記事ごとの上限 (`FOCUS_CVE_MAX`) | 値の頻度の上限 H | cos の閾値 |
|---|---|---|---|
| L0 | 3 (前回と同じ) | なし | 0.80 |
| L1 | 3 | 50 | 0.80 |
| L2 | 3 | 20 | 0.80 |
| L3 | 3 | 20 | 0.85 |
| L4 | 3 | 20 | 0.90 |

- 記事ごとの上限: 1 記事が持つ CVE (被害組織) が 3 を超える記事は、その欄を鍵にしない (前回と同じ)
- **値の頻度の上限 H**: 鍵の値ごとに、それを持つ記事の数を **DB 全体で**数え (CVE・被害組織 = `article_entities` の記事数、
  事象の根 = その根に属した記事の数 (`event_item_members` を最新の根に畳んだもの))、H を超える値は鍵にしない
  (成分を繋ぐ辺にも、母集合を広げる共有の探索にも使わない)。数え方を DB 全体に固定するのは、母集合に依存させない (循環させない) ため
- 辺・根の扱いは前回と同じ (最新の根 + 所属した全事象の根を鍵、被害組織は `normalize_for_match`、要約埋込は `snowflake-arctic-embed2`)
- **いつ計算するか**: 入力の凍結の直後、2 腕の実行の前。母集合 = 凍結した全 20 窓の `detect_input` の記事 ∪ §7.1 の学習・調整側 ∪
  共有の探索で到達した記事。各段の (成分数・最大成分・占有率) を `closure_plan.json` に全段ぶん残し、選んだ段と、凍結した窓の記事のうち
  学習・調整側と同じ成分に入る記事の集合 (汚染記事) を固定する。**2 腕の出力を見る前に段が決まる**
- L4 でも 0.30 以上なら判定不能 (GPU 枠を使わない)
- 2 腕の後: 単位の記事のどれかが汚染記事なら、その単位を除く。単位の記事が凍結の母集合の外にあれば (想定外) 汚染として除く (保守側)。
  成分を割らない・計算し直さない
- 凍結の時点の見込みとして、候補 (`llm_input`) の記事のうち汚染記事の割合を報告する。**50% を超えたら GPU 枠を使わずに調整役へ戻す**
  (R18 で単位の過半が落ちる見込みで、§6 の判定不能に近い)
