## 1. 仮説

救済の判定を PIR-driven の prompt (`GEO_RESCUE_PROMPT=pir`、SIR の title/description と境界の決まりを注入)
にすると、平たい prompt (`flat`、本番の現行) より、**PIR/SIR の文脈として分析に残すべき地政学の記事**
(正解 yes) を多く救い、残すべきでない記事 (正解 no) の誤った救済は少ないままである。

## 2. 母集団

- 表: `triage_rejections`、`ts >= '2026-10-12'` かつ `importance = 'low'` かつ `reason` が
  救済の正規表現 `src/pipeline/filters.py:_GEO_REASON` =
  `(地政学|軍事|外交|安全保障|海軍|演習|ミサイル|防衛|国防|核)` に当たる行 (測定スクリプトの
  `load_candidates` と同じ定義)。抽出時点 (2026-10-29) で 1,179 行・1,177 article_id・45 feed。
- 除外 (件数は manifest.json に記録):
  1. 同じ article_id が 2 行以上ある id (スクリプトの候補に重複行が入り標本が非決定になるため)
  2. 元のフィードを再取得して **URL か entry id で一致する entry が無い**行 (概要が得られない)
  3. 一致したが概要が空の行
- ⚠ **既知の偏り A (生存者の偏り、最重要)**: 本番は 10-02 から救済 (flat prompt、同じ
  `kuebiko-sft:26b`) を通しており、`triage_rejections` に残るのは**救済でも low だった記事だけ**
  (救われた記事は kept になり表に入らない。run_logs の `triage_geo_rescue` の集計で 10-12 以降
  候補 3,950・救済 211 = 5.3%)。したがって本母集団での flat の replay は救済がほぼ 0 になる
  (違いは非決定性と下記 B のみ)。**この測定が言えるのは「flat が取りこぼした記事を pir がどれだけ
  正しく拾うか (増分の回収)」と「pir の雑音」まで**で、「flat が救った記事を pir が失わないか (保持)」
  は測れない。採用の判断には保持の確認 (run_logs の `triage_decision` から救済候補の全体を復元した
  別の母集団) が別途要る。本測定の合格は「採用の必要条件」であって十分条件ではない。
- ⚠ **既知の偏り B (入力の差)**: 本番の triage は概要 (strip 後) が 600 字未満の thin feed で本文を
  先行抽出し (`_prefetch_thin_bodies`、`thin_feed_min_chars=600`)、救済も本文の冒頭 1500 字で判定した。
  本測定は指示により本文を取りに行かず、**題 + RSS 概要**だけで判定する。行ごとに `thin` (strip 後
  600 字未満) を summaries.jsonl に残し、指標を thin / 非 thin に分けても報告する (判定には使わない)。
- ⚠ **既知の偏り C (フィード保持)**: 現在のフィードに残る entry しか一致しないため、低頻度の feed と
  最近の記事に寄る。一致率と feed 別の一致数を manifest に記録する。

## 4. 標本と重み

- **測定の標本 (200)**: 除外後の母集団を `triage_rejections.id` 昇順に並べ、
  `random.Random(20261030).sample(pool, 200)` で抽出 (種はスクリプトの `SEED` と同じ)。
  summaries.jsonl にはこの 200 件**だけ**を書く → スクリプトの候補 = 標本 = 200 件 (全件を判定)。
  層別抽出はしない (スクリプトが単純無作為のため)。層 = `stratum_of(reason)` (最初に当たった
  地政学語) は件数を事後に報告する。
- **正解の標本 (60)**: 測定の標本 200 件から、
  - 層 G (30 件): 題 + 概要 (strip) が地政学の手がかり語に当たる行 — 枝の `GEO_THEATRE_TERMS`
    (紅海・ホルムズ・イスラエル/イラン・ウクライナ支援・台湾海峡・尖閣・南シナ海・朝鮮半島) と、
    pir_geo_* の主体語 (china/chinese/pla/taiwan/中国/台湾/russia/russian/kremlin/ukraine/nato/
    ロシア/ウクライナ/north korea/dprk/pyongyang/北朝鮮/iran/iranian/israel/houthi/イラン/
    イスラエル/japan/japanese/日本/自衛隊)。該当行から `Random(20261031)` で 30 件
    (該当が 30 未満なら全件、不足分は層 R に回す)
  - 層 R (30 件): 残りの行から `Random(20261032)` で 30 件
- 重み: 主要指標は正解 60 件の**無重み**。層 G を過剰抽出しているため、母集団の比率への外挿は
  しない (参考に層別の値を併記)。
- 正解は Opus (この下書きの作成者、claude-opus-5-5) が**flat / pir の出力が存在しない時点で**付ける。

### 正解のラベルの定義 (利用者の意図)

`rescue = true` ⇔ 「この記事は **PIR/SIR の文脈として分析に残すべき**」。地政学は、サイバーの
出来事を多角的に評価するための文脈として集める (Discord の高い警報に値するかでは**ない**)。
具体的には次のどれかを満たす:
1. pir_geo_china / russia / dprk / iran の範囲の動き (中国軍・海警の台湾海峡・南シナ海・東シナ海・
   日本周辺の行動、対日・対台湾の圧力・首脳外交・制裁 / ロシアの対ウクライナ・NATO の軍事行動・
   核の威嚇・欧州での破壊工作・日本周辺の活動・露朝/露中の連携 / 北朝鮮のミサイル・核・挑発・
   露朝の軍事協力 / イランと米・イスラエルの攻撃の応酬・湾岸・紅海の軍事事案)
2. 日本・同盟国の安全保障・防衛政策・同盟の動きで、上の敵対国の行動の評価に直接効くもの
3. サイバーと地政学の連関 (国家のサイバー戦略・影響工作・重要インフラへの物理/ハイブリッドの脅威等)

`rescue = false`: 上記の主体・戦域に結びつかない一般の軍事・防衛産業の商談/製品紹介、遠い地域の
内政・紛争で注視国が絡まないもの、国内の社会ニュース、論説で新しい事実のないもの、宣伝色が強く
事実の報告を含まないもの。判断は題 + 概要 (測定と同じ入力) だけで行い、理由を 1 文で残す。

## 5. 対の検定

- 同じ入力 (題 + 概要、同じモデル `step:triage_geo_rescue` = `kuebiko-sft:26b`、think=False) に
  flat と pir を当てる。救済 = 判定が medium 以上 (スクリプトの `KEEP`)。判定の失敗 (`error`) は救済なし。
- **主検定**: 正解 yes の行で、救済の判定の対の不一致 (pir だけ救済 c / flat だけ救済 b) に
  McNemar exact 両側 (`geo_rescue_stats.mcnemar_exact(b, c)`)。有意水準 0.05、多重比較なし
  (主検定は 1 本)。
- 副 (報告のみ): スクリプトの `summarize` の正誤の McNemar (正解 60 件全体)、正解 no での誤救済の対、
  200 件全体の救済率 (flat / pir)、層別・thin 別の値、回収率・誤救済率の Wilson 95% 区間。

## 6. 合否の線 (結果を見る前に固定)

正解 60 件 (標本に入るのは定義上 60/60) で、次の**すべて**を満たせば合格:
1. 回収率の差: `recall_pir − recall_flat ≥ +20 pt` (正解 yes の行での救済率)
2. 主検定の McNemar exact 両側 `p < 0.05`
3. pir の誤救済率 (正解 no の行での救済率) `≤ 20%`
4. pir の 200 件全体の救済率 `≤ 50%` (雑音の総量の歯止め。超えたら不合格)

無効 (判定しない) の条件: 判定の失敗が どちらかの腕で 200 件中 10 件超 / 正解 yes が 10 件未満
または 正解 no が 10 件未満 (検出力が無い)。
偏り A のため、合格でも「採用」ではなく「保持の確認へ進む」。

## 7. 汚染の鍵 (R18)

- 正解 60 件は本測定のために新しく作る集合 (tainted でない)。
- 落選した記事は `articles` に行が無く (事象の根・要約埋込なし)、R18 の閉包 (事象の根・CVE・
  被害組織・cos ≥ 0.80) は計算できない。代わりに、調整に使った集合 (triage の境界・平たい triage 150、
  いずれも 10-12 より前の記事) と窓が重ならないことで独立とみなす (限界として報告に書く)。
