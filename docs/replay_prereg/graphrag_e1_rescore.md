### 4.0 判定の手順 (Opus `claude-opus-5-5`・effort high・temperature 0・`data/mlx/adjudication_cache.py` 経由)

### 4.1 対読 (90 回 = 45 窓 × 2 順)

- 各窓を 2 回採点する。順 AB = X に腕 A・Y に腕 B、順 BA = X に腕 B・Y に腕 A。1 回の呼び出しは 1 窓 1 順。
- 入力: `prompt_b` の全文 (書き手への指示・記事・線の節) を「入力」として、出力 X・Y を本文のまま渡す。
- 判定役の指示 (逐語。`scripts/graphrag_eval/prompts.py` の `E1_PAIRWISE_RUBRIC`):

> あなたは CTI 部門の上級分析官です。同じ入力から書かれた 2 つの出力 (X と Y) を比べ、読み手 (日本の CTI 担当者) の判断にとってより良い方を選びます。
>
> 入力の全文を示します (書き手への指示を含む)。入力には「線でたどった関連事象」の節が含まれます。この節は、共有する指標 (攻撃者名・CVE・道具など) から機械的に導いた候補の関係であり、記事が裏付ける事実ではありません。出力がこの節を使っているかどうか自体は評価しません。
>
> 観点:
> 1. 根拠: 主張が入力 (記事、または線の節が述べる範囲) に裏付けられているか。入力に無い主張・関係の推測・確度の格上げ (例: 同じアクターというだけで同一キャンペーンと書く)・出典番号の誤った帰属は大きく減点する
> 2. 判断への有用さ: 重要な事実・含意・事象どうしの関係のうち、読み手の判断を実際に変えるものを正しく示しているか。言い換え・繰り返し・水増しは評価しない
> 3. 見通し・留保: 分からないことと次に確かめることが具体的か
>
> 長さそのものは評価しません。長い方を、情報が多いという理由だけで選ばないでください。
> 各観点で優れた方 (X / Y / 同等) を選び、最後に総合の勝者 (X / Y / 同等) を決め、理由を 2-3 文で書きます。理由には出力の該当箇所を具体的に挙げます。

- 問い: 「課題: {課題の説明}。2 つの出力 X と Y を上の観点で比べてください。」(課題の説明は `TASK_DESC`)
- 出力: grounding / usefulness / outlook / winner (各 X / Y / 同等) と reason。
- **旧の物差しからの変更とその理由**: 旧の対読は観点 1 を「つながり (連鎖・継続性) を捉えているか」とし、
  「線は一方の書き手にしか渡されていません」と明示していた。文脈を足すほど有利になる物差し (§0 (a) の偏り) なので、
  つながりを有用さの一部に下げ、線の節の使用そのものを評価しないと明記した。
- 記録: 各判定に `len_a` / `len_b` (腕の出力の字数) を残す。

### 4.2 主張の照合 (45 回 = 1 窓 1 回)

- 入力: 「記事の節」= `prompt_a` の全文、「線の節」= `prompt_b` で挿入された節、出力 X・Y (X/Y への腕の割り当ては
  窓ごとに `random.Random(20261102)` で決める。窓は課題 → ファイルの行の順に回す)。
- 判定役の指示 (逐語。`E1_CLAIM_RUBRIC`):

> あなたは CTI 文書の事実確認の担当です。2 つの出力 (X と Y) から主張を取り出し、それぞれが入力に裏付けられるかを判定します。
>
> 入力は 2 つの節に分けて示します。
> - 「記事の節」: 書き手への指示と記事 (または台帳の判定と証拠記事)
> - 「線の節」: 共有する指標から機械的に導いた候補の関係 (記事が裏付ける事実ではない)。出力によってはこの節を受け取っていない
>
> 手順:
> 1. 各出力から、確かめられる主張 (事実・数値・日付・帰属・事象どうしの関係) をすべて取り出す。1 つの主張は 1 つの事実。見出し・本文・箇条書きのすべてが対象。見通し・推測であることを明示した文 (「〜の可能性」「〜を確かめる必要」) と、書き手への指示の言い換えは取り出さない
> 2. 各主張の support を 1 つ選ぶ
>    - 記事: 記事の節に裏付けがある
>    - 線の節のみ: 記事の節には無く、線の節が述べる範囲に裏付けがある
>    - 裏付け無し: 入力のどこにも無い・入力と矛盾する・入力より確度を上げている (例: 線の節が「同じアクター」とだけ述べる関係を同一キャンペーン・同一事象と書く)
> 3. misattributed: 主張に出典番号 ([n] など) が付いているが、その内容が線の節にしか無い場合 true
>
> text は主張を 40 字以内に縮めて書く。

- 問い: 「出力 X と出力 Y のそれぞれから主張を取り出し、上の手順で判定してください。」
- 裏付けの定義 (腕ごと): 腕 A は support = 記事 のみを裏付けありと数える (A は線の節を受け取っていない)。
  腕 B は 記事 または 線の節のみ を裏付けありと数える。misattributed は腕 B の型① として別に数える (裏付けの率には影響させない)。
- 裏付け率 = 課題ごとに、全窓の裏付けありの主張の数 / 主張の総数 (窓を合算)。

### 4.3 失敗と再試行

呼び出しの失敗 (例外・形の検証の失敗) は同じ入力で 2 回まで再試行する (再試行も Opus の回数に数える)。
それでも失敗した窓は「欠け」とし、その課題は §6 で「未確定」になる。

任意の Sonnet の審判 (計画の ④) は**しない** (利用者の指示)。

## 5. 対の検定

- 同じ窓に両腕を当てた対の比較。主の量は**提示順ごとの**線つきの勝ち数 (順を合算しない)。
- 参考の検定 (合否に使わない): 両順を合わせた B 勝ち / A 勝ちの符号検定 (同等を除く、両側の正確検定)、
  窓ごとの裏付け率の差 (B − A) の bootstrap 区間 (窓の再抽出、種 20261102、2000 回)。
- 課題ごと (spotlight / synthesis / eventnews) に独立に判定する。多重比較の補正はしない (3 課題は別の判断に使う)。

## 6. 合否の線 (結果を見る前に固定)

- **維持**: 順 AB と順 BA の**両方**で、線つき (B) の総合の勝ちが **≥ 10/15** (同等は勝ちに数えない)、**かつ**
  主張の裏付け率の差 (B − A) が **≥ -3pt** (非劣性)。
- **評価の産物**: どちらかの順で B の勝ちが **≤ 9/15** (順で逆転する場合を含む)。
- **裏付けで不合格**: 勝ちの線は満たすが裏付け率の差が -3pt 未満。
- **未確定**: 欠けた窓がある。
- 参考 (合否に使わない): 両順で同じ腕が勝った窓の数・先に出した方 (X) の勝ちの数 (位置の偏り)・§5 の検定・長さの差 (B − A の字数) と勝ちの関係 (B が長い窓 / 長くない窓
  ごとの B の勝ち率)・観点ごとの勝敗・腕 B の misattributed の数。
- §6.3 との対応: 3 課題のうち 1 つでも「維持」なら、その課題について「効く」を維持する。Spotlight と総括がともに
  「評価の産物」なら、n21 に線の腕を入れない (GRAPHRAG を UI と点検だけに縮める案へ)。事象ニュースは E5 の形が前提。
