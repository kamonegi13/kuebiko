## 1. 仮説

10-02 に入れた低確度の反転の保留 (1 回目は前回の見立てを保ち、次の評価で同じ見立てが首位なら確定。
確かな出所の反証が根拠なら即確定) により、「次の改訂で元に戻る反転」の率が、10-02 より前の約 20% (20/103、区間 13〜28%) から
目標の 5% 以下へ下がる。向き = 下がる。指標 = 確定した反転のうち次の改訂で反転前の見立てに戻ったものの割合。

## 2. 定義 (数える前に固定)

- **確定した反転** = `situation_revisions` の行 r で `delta_type = 'hypothesis_flip'`
  (`leading_hypothesis` が r−1 と違い、休眠からの再開ではない)。保留された反転は行 r の見立てが前回のままなので、
  ここには入らない
- **元に戻る** = 同じ `situation_id` の次の行 r+1 の `leading_hypothesis` が r−1 の `leading_hypothesis` に等しい
  (r−1 ≠ r)。r+1 の `delta_type` が `reopened` / `closing` のものは「次の改訂」と数えない (観測できない扱い)
- **観測できる反転** = 次の行 r+1 が存在し、`created_at` が r から 14 日以内。**分母は観測できる反転だけ**。
  r+1 が無い・14 日を超える反転は分母に入れず、件数だけ報告する (最後の行の反転は結果が未確定で偏るため)
- **反転の率** = 元に戻った観測できる反転 ÷ 観測できる反転

## 3. 母集団と窓

- 表: `situation_revisions` (本番の PostgreSQL)
- 窓 (JST) = **2026-10-03 00:00 以上 2026-11-10 00:00 未満** の `created_at`。数えは 11-10 に行う
  (11-10 00:00 以降に作られた行は r+1 にも使わない。窓の端で r+1 が切れた反転は観測できない扱い)。
  10-02 の保留の投入より後だけを窓にし、投入前の約 20% は比較の基準 (探索の値) として使う
- 除外 (件数を層別に報告):
  1. 評価・教師収穫・再生の実行が書いた行 (`run_id` が本番の run の記録に無い、または評価用の印があるもの)
  2. `situation_id` が標準の常設の問い (`STANDING_KIND`) のものは**除外せず**、別に層として報告する
     (常設の問いは seed の仮説が固定で、反転の意味が通常の台帳と違いうるため。合否の主解析には含める)
- 窓の中の台帳の関連の変更 (期間の分割に使う。合否には使わない): 10-19 の主語の関門と台帳内部の文の持ち越し止め
  (`LEDGER_CLAIM_SUBJECT_GATE` / `LEDGER_CLAIM_INTERNAL_RESET`)。10-03〜10-18 と 10-19〜11-09 に分けた値を併記する
- 期間の分割の定義は事象時刻ではなく `situation_revisions.created_at` (改訂を書いた時刻そのもの) を使う。
  バックフィルで過去の日付に書く経路は revision にないので、書いた時刻が改訂の時刻と一致する
  (ここは entity の `created_at` と事情が異なる。確かめた結果は報告に書く)

## 4. 標本と重み

- **率の計算 (主)** は窓の観測できる反転の**全数**。標本抽出なし・重みなし
- **区間**: `situation_id` を単位とするクラスタ bootstrap (10,000 回、`random.Random(20261110)`)。
  同じ situation の反転は相関するため、反転単位の Wilson は参考として併記するだけで線には使わない
- **Opus の標本 (50 件)**: 観測できる反転から
  - 層 R (元に戻った) = `min(25, |R|)` 件、層 K (戻らなかった) = `50 − |層 R の件数|` 件
    (R が 25 に満たなければ K で埋めて合計 50)
  - 抜き方: 層の中で `(situation_id, rev)` の昇順に並べ、`random.Random(20261112)` で混ぜ、
    **同じ `situation_id` は 1 層あたり最大 3 件**まで (超えた分は飛ばして次を取る)
  - 重み = 層の件数 ÷ 抜いた件数 (逆確率重み)。層の件数が 25 に満たず全件を取った層は重み 1
  - 反転の総数 (観測できる) が 30 未満なら、Opus の標本は全件 (50 に満たなくてよい)。主の率が判定不能 (§6) になる場合も同様

## 5. Opus の問いと正解 (盲検)

- 付け手は新しい文脈の Opus (50 回、1 件 1 回、再採点なし)。**見せるもの**: 状況の題・問い、
  r−1 の見立てと確度、r の見立てと確度と結論文、r の時点で台帳が持っていた証拠
  (記事の題・要約・出所の種別・賛否の向き。本文は渡さない)、新しく加わった証拠の印
- **見せないもの**: r+1 以降の行・元に戻ったか否か・層・本書・反転の保留の有無・`delta_note`
  (後続の事実から結果を推測させない)
- **問い**: 「r の時点の証拠だけで、見立てを r−1 から r に変えるのは正当か」
  - `justified` = 新しい証拠 (または確かな出所の反証) が見立ての変更を支える
  - `unjustified` = 変更を支える新しい根拠が無い、同じ証拠の読み替え・言い換え、表現のゆらぎ
  - `unclear` = 証拠から判断できない
  - 各件に確信度 (high / low) と理由 1 文を付ける
- 正解の用途は §6 の副次と、元に戻った反転が「ノイズ」か「実際の変化の揺れ」かの切り分け。主の合否は DB の数だけで決まる

## 6. 合否の線 (結果を見る前に固定)

主 (DB の数のみ。Opus は使わない):

1. **達成** = 反転の率の点推定 ≤ 5% (目標、`accuracy_targets.md` §4.4)
2. **改善** = 反転の率のクラスタ bootstrap 95% 区間の上限 < 20% (10-02 前の点推定。上限が 20% 未満なら、少なくとも
   10-02 前の水準を統計的に下回る) 。達成でなく改善のとき「改善、目標未達」と報告する
3. 上のどちらも満たさなければ「未改善」
4. **判定不能**: 観測できる反転が 30 件未満、または観測できる反転が窓の反転の総数の 50% 未満のとき。
   判定不能のときは率を報告するだけで 達成・改善 を名乗らない。件数が足りないとき窓を延ばさない
   (延ばすなら新しい事前登録を書く)

副次 (Opus の標本、合否には使わない):

- **ノイズ反転率** = 反転のうち「元に戻った ∧ Opus が `unjustified`」の重み付きの割合 (層 R の `unjustified` の割合 ×
  R の件数 ÷ 全体)。層別 bootstrap (10,000 回、`Random(20261113)`) の 95% 区間を併記
- 層 R の `justified` の割合 (戻ったが変更自体は正当だった = 実際の変化の揺れ) と、層 K の `unjustified` の割合
  (戻らなかったが根拠のない反転 = 取りこぼし) を報告する
- 保留の挙動 (報告のみ): 窓の中で保留された反転の件数 (`delta_note` が `PENDING_FLIP_MARKER` で始まる行)、
  そのうち次の改訂で確定した件数・取り下げられた件数・次の行が無い件数。確かな出所の反証で即確定した反転の件数
  (r の `evidence` の `contradicts` で強い出所のもの)
- 期間別 (10-03〜10-18 / 10-19〜11-09)、常設の問い / 通常の台帳別、確度別の率

## 7. 汚染の鍵と判定集の同一性

- 学習・調整を伴わない測定で、窓の改訂は運用が生んだ記録。R18 の閉包の対象外 (n/a)
- Opus の標本は 窓の反転から作るので、既存の正解集と重ならない。標本の manifest に標本の各行の `situation_id`・`rev` と
  sha256 を残し、判定集のパスと sha256 は実行時に台帳へ記録する (作る項目の id = AT-3)
- manifest に `prereg_path`・`prereg_git_sha`・`prereg_blob_sha256` を必ず書き、実行前に
  `git merge-base --is-ancestor` で prereg が実行のコミットの祖先であることを確かめる (README のとおり)
