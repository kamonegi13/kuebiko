# 事前登録: 頻出の名前だけを共有する近い時期の事象の統合 (EVENTNEWS_MERGE_FREQUENT_RECENT)

- 登録: 2026-11-21 (標本を抜いた後・Opus の正解付けの前にコミットする)
- 発端: 同じ出来事 (Cairn による医療画像 AI 基盤のゼロデイ悪用) が事象ニュースで 4 事象に割れていた (手動で統合済み)。

## 問題 (本質)

事象の統合・群化は、**頻出ガード (14 日で 12 記事超の名前は結合に使わない) をくぐった固有名の共有**だけで
候補を作る。頻出ガードは「道具・アクター・組織の名前だけで結ぶと別の事案が潰れる」を防ぐ正しい歯止めだが、
外した後に代わりの手がかりが無い。救済 (頻出の名前 + 本文 cos 0.80 以上、10-02) は大きな事案の後追い記事の
cos (0.5〜0.78) に届かない。結果として**何度も報じられる名前の、新しい大きな事案ほど割れる**
(CVE で 08 月に起きた逆転と同じ型)。11-21 の生きた事象で、頻出の名前だけを共有し cos < 0.80・ML 承認の
事象の組は 24h 以内 280 / 72h 以内 475 (Binance の窃取・Optimizely・ATF と Qilin など)。

## 変更 (旗)

`EVENTNEWS_MERGE_FREQUENT_RECENT=0|shadow|1` (`src/eventnews/merge.py:frequent_entity_pairs`)。
頻出の名前を共有する別事象の記事対を、cos ≥ 0.80 **または** (記事の時刻の差 ≤ G 時間) で候補にし、
判定は既存の ML に回す。ML の承認に追加の下限 P (確率) を掛ける (cos ≥ 0.80 の従来の組には掛けない)。
その後の関門 (焦点の照合・ハブ・閉包の照合し直しなど) は従来どおり。shadow はログのみ。

## 標本 (凍結)

`data/eval/cairn_split_1121/frequent_pairs.json` (11-21 12:3x JST、本番と同じ入力の読み取り) から、
cos < 0.80・ML 確率 ≥ 0.60・時刻差 ≤ 168h の記事対を事象の組ごとに 1 つ (確率が最大の対) にまとめ、
確率 3 帯 [0.60, 0.75) / [0.75, 0.85) / [0.85, 1] × 時刻差 3 帯 ≤24h / (24, 72] / (72, 168] の 9 層から
各 6 組 (乱数種 20261121)、計 54 組。`data/eval/cairn_split_1121/sample.jsonl`
(sha256 `4b684ae2c8415cd613ebefb11e2ce1db98bc80157473bce2b6acdb91807a073e`、道具 `data/eval/cairn_split_1121/tools/label_pairs.py`)。
層の母数 (確率帯 × 時刻差帯): 108 / 88 / 140 / 82 / 49 / 48 / 76 / 37 / 19。

## 正解

- Opus 5.5・effort high・1 回 1 組・盲検 (ML の確率・cos・事象の id は見せない)。
- 材料: 2 記事の題・媒体・公開時刻・本文全体と、`docs/event_identity_definition.md` §1 の定義 (逐語)。
- 出力: same / lineage (系統: 修正 ⇔ 悪用・派生) / contains (まとめ・包含) / different / boundary。
- 2 回独立、割れたら 3 回目で多数決、2 回で割れた組は境界。
- **統合として正しいのは same だけ** (lineage・contains・different は誤統合)。

## 線 (この登録で固定する)

候補の範囲 (P, G) を広い順に (0.75, 72) → (0.75, 24) → (0.85, 72) → (0.85, 24) と試し、範囲に入る標本の組
(境界を除く) で誤統合が 1 件以下かつ適合率 ≥ 0.95 を満たす**最初の**範囲を採る。
- 満たす範囲があれば、その (P, G) で旗を 1 にする (利用者の指示 11-21「本質を解決する」による)。
- どれも満たさなければ旗は shadow のまま、誤りの型を報告する。
- [0.60, 0.75) の層と 72〜168h の層は線の外 (参考の数字。どこまで広げられるかの見込み)。

## 合格の確かめ

このコミットの hash が Opus の台帳の `MERGE-FREQ-RECENT-GOLD` の最初の行より前であること。

## 結果 (1 回目) と追記 (2026-11-21、2 回目の標本の正解の前)

- 1 回目 (54 組、`MERGE-FREQ-RECENT-GOLD`): どの範囲も線に届かず (P0.75-G72 で適合 0.696・誤り 7/23)。
  same 32 / contains 12 / different 5 / lineage 1 / 境界 4。確率 0.75 以上の誤り 7 件のうち 6 件が
  **流出サイトの掲載の型** (「LockBit 5.0、被害組織 6 件を掲載」⇔「LockBit: victim-a.example」= 束と 1 件)。
  different は確率 0.75 未満の層にだけ出た。
- 対処: グループ名 (actor / malware_family) だけを共有し、片方が流出サイトの掲載の形 (rl_ の記事・
  題にリークサイト / ダークウェブ・「グループ名: 被害者」) の組を、近さの候補から外す
  (`src/eventnews/leak_listing.py`)。**この規則は 1 回目の標本を見て作った** (1 回目で当たる 11 組は
  全て誤り・same は 0 組を巻き込む。同じ標本の値なので判定には使わない)。
- **2 回目の標本 (判定に使う)**: 1 回目と同じ候補表から、cos < 0.80・確率 ≥ 0.75・時刻差 ≤ 72h・関門に
  当たらない・1 回目の事象の組と重ならない組を、確率 [0.75, 0.85) と [0.85, 1] から各 15 組

- **線**: (P 0.75, G 72h) の 30 組 (境界を除く) で適合率 ≥ 0.95 (= 誤り 1 件以下) → その範囲で旗を 1。
  届かなければ (P 0.85, G 72h) の 15 組で適合率 ≥ 0.95 (= 誤り 0) → その範囲で 1。

## 結果 (2 回目、判定)

- `MERGE-FREQ-RECENT-GOLD-2` (30 組): same 22 / contains 6 / lineage 1 / 境界 1。
  (P 0.75, 72h) 適合 22/29 = 0.759、(P 0.85, 72h) 13/15 = 0.867。**どちらも線に届かず → 旗は shadow のまま**。
- 誤りの型: 流出サイトの掲載で題に掲載先の語が無いもの (「Qilin、米国の 5 組織を新たな被害者として公開」⇔
  ATF の件)・道具の解説 ⇔ その道具による被害・同じアクターの作戦 ⇔ その中の 1 件。
- 注記 (判定は変えない): 同じ事案の第 n 報と読める組 (Binance の窃取の報道 ⇔ FBI の帰属、PHP2Shell の同じ 216 台の
  別言語の報道) を Opus が 2 回とも contains とした。指示 (定義 §1 の逐語) で「包含」が「束と 1 件」に限られることが
  伝わっていない疑いがある。次に測るときは指示を直し、新しい標本で付け直す。

## 追記 3 (2026-11-21、指示 v2 と誤りの型の関門。検証用の標本の正解の前・関門を作る前)

- **指示 v2**: 定義 §1 の逐語に「定義の読み方 (補足)」を足す (`label_pairs.py` の `_READING_V2`)。
  contains は片方が別々の複数の事案を並べた記事のときだけ・同じ事案の続報 (帰属の発表・当局の警告を含む) は same・
  別の主体の否定・声明・処分は lineage・解説 ⇔ 特定の被害は different。定義の表と問い 2・4 の書き下しで、定義は変えない。
  動機: 2 回目で第 n 報と読める組を contains としていた。
- **開発用** (関門を作る材料、判定には使わない): 1・2 回目の 84 組を v2 で 1 回ずつ付け直す (`dev_gold_v2.jsonl`、
  台帳 `MERGE-FREQ-RECENT-GOLD-DEV-V2`)。
- **検証用 (判定に使う)**: 1・2 回目と同じ候補表から、cos < 0.80・確率 ≥ 0.75・72h 以内・掲載の関門 v1 に当たらない・
  1・2 回目の事象の組と重ならない組を、確率 [0.75, 0.85) / [0.85, 1] から各 25 組 (乱数種 20261123)、計 50 組。
  `sample3.jsonl` (sha256 `62f8b4b1cd294c7aa08b9112eec2d7a9ef22d845753f4a8ece7f48c404560f0c`、母数 71 / 76)。
  v2 で 2 回 + 割れたら 3 回目 (台帳 `MERGE-FREQ-RECENT-GOLD-3`)。
- **線**: 開発用で作った関門 (コミットした版) を検証用の 50 組に当て、関門を通った組 (境界を除く) で
  (P 0.75, 72h) が n ≥ 20 かつ適合率 ≥ 0.95 → その範囲で旗を 1。届かなければ (P 0.85, 72h) が n ≥ 10 かつ
  適合率 ≥ 0.95 → その範囲で 1。どちらも届かなければ shadow のまま。
  **関門が検証用の same の 25% 超を外したら**、適合率に関わらず判定不能として報告する (回収を捨てて適合率を買っていないか)。

## 結果 (3 回目、判定)

- 開発用 (指示 v2・84 組・判定外): 関門 (e5f9e9e7) を通った組で same 37 / 誤り 5 (0.88)。
- **検証用 50 組** (`MERGE-FREQ-RECENT-GOLD-3`、2 回で割れた組 3): 関門で外れた same は 40 組中 2 (5%、25% の線の内)。
  (P 0.75, 72h) = 38/41 = 0.927 → 不合格。**(P 0.85, 72h) = 19/20 = 0.95 → 合格**。
  残った誤りは系統 1 (別主体の対策の発表)・束 1 (論評)・別の被害者 1。
- 判定に従い、`EVENTNEWS_MERGE_FREQUENT_RECENT=1`・`_MIN_P=0.85`・`_GAP_HOURS=72` を本番の `.env` に書く。
  n=20 の点推定で、区間は広い (おおよそ 0.75〜0.99)。週次の止めた組の抜き出しとは別に、統合の判断記録から
  この経路の組を週 10 組抜いて裁定し、0.9 を割り続けるなら shadow に戻す。
