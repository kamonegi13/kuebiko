## 1. 仮説

s26 の P(中身あり) に R3 で較正した閾値を当てた 2 段目 (A) は、中身の無い短い本文を回収し、中身のある
記事への誤発火が小さい。閾値の見直し (B) は、A より誤発火を増やさずに回収を上げる場合にだけ採る
(既定は A のまま)。

## 4. 標本と重み

- 層: 本文の長さ (`len(body.strip())`) の帯 **<300 / 300-450 / 450-600 字**、各 **50 件** (計 150)
- 抽出: 各帯の適格な記事を `article_id` の昇順に並べ、`random.Random(20261103)` で帯ごとに
  (<300 → 300-450 → 450-600 の順に、同じ乱数の列で) shuffle し、先頭から 50 件
- 不足のとき (1 回だけの決まり): ある帯の適格な記事が 50 未満なら全件を取り、不足分を次に短い帯
  (<300 の不足は 300-450、300-450 の不足は 450-600、450-600 の不足は 300-450) に足す。計 150 を超えない。
  作成時点では <300 帯が 40 件 (11-02 までに 50 に届くか未確定)
- 重み: 帯 h の母集団の件数 N_h / 標本の件数 n_h (抜き出しの確率の逆数)。率は R3 と同じ定義の母集団
  (10-12〜11-02) へ戻した重みつきの値で出す
- 選び出しは決定論で、**GPU-D1 (s26 の採点) の前に固定**する。標本の `article_id`・帯・重み・
  `body_sha256` (本文そのものは書かない)・`gate_status` を `data/eval/thin_fresh_1103/sample.jsonl`
  (gitignore) に書き、manifest に sha256 を残す

## 5. 正解 (Opus、盲検)

- Opus に渡すのは **見出し・本文 (保存された本文をそのまま) ・出典 (購読ソースの名前)** だけ。
  モデルの判定・確率・1 段目 / 2 段目の結果・`gate_status`・帯・他の記事は見せない。順は乱数で並べ替える
- 問い: 「この本文は記事の中身 (出来事の事実や主張) を具体的に書いているか」。答えは 3 つから 1 つ:
  - `thin` (中身が無い): 見出しの繰り返し、音声・動画・イベント・ウェビナーの告知、登壇者・目次の一覧、
    「詳細はリンク先」の定型、ログイン・購読の案内だけ
  - `content` (中身がある): 出来事の事実・主張を 1 つ以上具体的に書いている (短くてもよい)
  - `boundary` (境界): 事実らしき断片はあるが、それが記事の中身として足りるか判断が割れる
- 1 記事 1 回 (Opus 150 回)。全件に一言の理由を付けさせる (ラベルの監査用、判定には使わない)
- 裁定は `data/eval/adjudication_ledger.jsonl` に記録 (R23)
- 正解集の id は `gold:thin_fresh_1103` (台帳の `gold_sets`)。学習・調整に使わない

## 6. 判定 (THIN-JUDGE) と合否の線

### 6.1 腕と入力

- s26 の P(中身あり) を GPU-D1 で 150 記事に当てる (本番の `_thin_body_probe_question` と
  `decision_probe.probe_choice`、Step.THIN_BODY_JUDGE、温度 0)
- **A (今)**: SW-S26 が入れた s26 の行の閾値 (PROBE-ROWS-S26 が R3 で較正した値)
- **B (見直し)**: **GPU-D1 の採点の前に**、R3 と版 44 の測定集 (`data/eval/probe_calib/thin_body_judge.jsonl`)
  だけで決めた 1 つの閾値。値と決め方を本書の変更履歴 (§10) に書いてから採点する。
  書かれていなければ B は無く、THIN-JUDGE は A の率を報告して SW-THIN を出さない

### 6.2 指標

- 主の指標は `boundary` を除いて計算する (境界の件数と、境界を `thin` / `content` に倒した 2 通りの感度も出す)
- 回収 = 重みつきで `thin` のうち 2 段目が落とす (P < 閾値) 割合、誤発火 = 重みつきで `content` のうち落とす割合
- 対の検定: 同じ記事で A と B の正誤の不一致に McNemar の正確検定 (両側、`scripts/replay/_stats.mcnemar_exact`)
- 区間: 帯の中で記事を復元抽出する bootstrap 2,000 回 (`random.Random(20261103)`、1 回の抽出に両腕を当てる
  対応のある形)、95% パーセンタイル区間
- 床: `thin` (境界を除く) が **20 件未満なら回収の比較は「判定不能」** (A のまま、SW-THIN を出さない)

### 6.3 合否 (B を採る条件、すべて満たす)

1. 回収の差 (B − A): 点推定 > 0 かつ、`thin` の不一致に McNemar で p < 0.05 (B の向き)
2. 誤発火の差 (B − A): bootstrap 95% 区間の上限 ≤ +1.0 点
3. B の誤発火の重みつきの点推定 ≤ 3% (閾値の元の選び方「中身のある記事への誤発火 ≤3%」、`briefing.py` の注)

- 満たさなければ A のまま (SW-THIN を出さない)。代わりの案は置かない
- 参考に A の回収・誤発火を版 44 の本番の値 (回収 67%・誤発火 0.6%、版 44 の測定集) と並べて報告する
  (合否には使わない。測定集が違うため)
