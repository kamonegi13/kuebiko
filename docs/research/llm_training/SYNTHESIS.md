# 統合考察: この用途に特化した LLM を post-training で作る (2026-09-05)

10 本の調査ノートと手元の実測 (v1/v2/v3) を突き合わせた設計考察。
**結論から書く: 「1 つの万能特化モデル」ではなく「勝てる課題に小さく強い特化を置き、
narrative は最強モデルとのハイブリッドを保つ」構成が、文献と実測の両方に支持される。**

## 1. 実測と文献が同じ絵を描いている

| 手元の実測 | 文献の対応物 |
|---|---|
| triage: Sonnet 一致 55→71%、抽出: IOC で教師超え | LoRA Land「固定タクソノミーの抽出・分類は特化 SFT が GPT-4 に勝つ (25/31 タスク)」 |
| 事象ニュース narrative だけが難航 (v2 で悪化) | 「自由度の高い narrative は汎用大規模が依然強い」 |
| 契約 (空欄・重複) は 150 反復で習得 | LIMA「形式は少データで飽和」 |
| ATT&CK 抽出は 700 反復で教師の 39% | 「模倣データに薄いタスクはギャップが閉じない」「長尾が最初に壊れる」 |

**SFT が勝ちやすい場所と苦しい場所は、課題型でほぼ決まっている。**
戦略はこの非対称性に沿わせるのが素直。

## 2. 設計の 3 案

### 案 A: 現行路線の完成 (Gemma 4 26B MoE・単一多タスクモデル)

v3 (混合比 2:1:1) が事象ニュースの慎重さを回復させれば成立する。
- 利点: 追加の移行コストゼロ。単一モデルで運用が単純
- 弱点: MoE ゆえ**アダプタ単体の配備が塞がっており**、反復のたびに fuse→変換 (47GB×2、
  約 1 時間) を払う。narrative が Opus 級に届く見込みは文献上薄い
- **v3 の評価結果が採否を決める**

### 案 B: dense 基盤へ移行し、課題別の特化を薄く持つ

Swallow 8B (高速・JP 特化) を「勝てる課題」(triage / 抽出 / 要約) に強く鍛え、
アダプタ経路 (dense なら枯れている) で反復する。
- 利点: 学習サイクルが 26B の数分の一。triage は ~2,000 呼出/日なので速度がそのまま効く。
  LoRA→GGUF→Ollama の枯れた経路が使える
- 弱点: 移行の検証コスト (評価セットの再較正)。8B の narrative 上限。
  ⚠ 複数アダプタの常駐 hot-swap はどの基盤も未成熟 (llama.cpp は KV 汚染バグ #26207)
  なので、**運用は fuse 済み per-task モデルが現実解のまま**

### 案 C: ハイブリッド (文献の勝ち筋への割り付け) ← 推奨

- **勝てる課題は特化ローカル**: triage / article_summary を小さい dense (案 B の車両) で
- **narrative は外部 (Opus/Sonnet) を維持**しつつ、蒸留の改善を継続 (v3 の知見を反映)
- **契約違反は RLVR で潰す**: repo の関門 (識別子・引用・スキーマ) は reward hacking に
  強い rule-based 報酬そのもの。SFT→RL の順序に +15% の実証。
  ただし MLX の GRPO は未成熟 → 数百プロンプトの小規模 PoC から
- **鮮度は学習に持たせない**: actor 辞書 / MITRE sync / rubric-in-DB が担う現行設計を維持
  (CTI 文献の RAG vs FT 論と整合)

## 3. どの案でも共通に確定した方針

1. **CPT (継続事前学習) は見送り** — 実績下限 (数億トークン) の一桁下
2. **教師は Opus 単一を維持** — 複数教師の単純平均は害 (MOPD)
3. **教師データ 2,273 対・凍結評価 3 セット・混合比の知見は基盤を替えても持ち運べる**
4. **rationale は学習時のみ補助信号として使える** (Distilling Step-by-Step) —
   推論時のスキーマは変えずに CoT 蒸留の利得を取れる。次の教師データ生成で検討
5. 評価は「現行との差分」でなく「独立参照 + 決定論的関門 + 床」で。
   39/86/150 件では稀少クラスの見逃しを統計では検出できない → 関門で止める

## 4. 直近の分岐

```
v3 の 3 評価 (実行中)
 ├─ narrative 回復・他維持 → 案 A で当面継続。案 C の RLVR PoC を並走
 └─ narrative 回復せず     → 案 C へ。narrative は外部維持、
                             勝てる課題の特化を案 B (Swallow 8B) で検証
```

どちらに転んでも、**評価基盤・教師データ・関門は共通資産**であり無駄にならない。
