# 微調整済み LLM の評価 — 静かな劣化の検出 (調査: 2026-09-05)

> ⚠ 出典は調査時に収集したもの。筆者が独立に再検証したものではない。

## ⭐⭐ 今日踏んだ 2 つの落とし穴は、文献上の主要な失敗パターンだった

**1. 現行モデルの出力を基準にした** → **循環評価バイアス (circular evaluation bias)**。
モデル自身の出力を参照にすると、評価は「変更の正しさ」ではなく「現状との乖離」だけを測る
([arXiv:2509.19880](https://arxiv.org/html/2509.19880))。

**2. 充足率で判定し、抽出件数 4.9 倍を見逃した** → **structured hallucination / over-generation**。
小型モデルほど「無い情報でも値を生成し recall だけ高く precision が崩壊する」傾向が実証
([ExtractBench, arXiv:2602.12247](https://arxiv.org/html/2602.12247v2))。

どちらも既知の型で、私は両方を独自に踏み直した。

## 基準の置き方

- 実務ガイドは一致して「**現行の生成物を参照にしない**、独立な held-out を用意し新旧双方を採点」
  ([OpenAI](https://developers.openai.com/api/docs/guides/fine-tuning-best-practices))
- 参照そのものの質にも注意 — 要約では生成物が「金標準」参照を上回る例が実証済み
  ([eugeneyan](https://eugeneyan.com/writing/evals/))
- ⚠ **次元間トレードオフ**: 抽出 100%→90%、RAG 適合性 93.3%→80% に落ちる一方で指示追従は改善、
  という実例 ([arXiv:2601.22025](https://arxiv.org/html/2601.22025v1))。軸の優先度を明示しないと
  無関係な指標を最適化する

## 指標の選び方

- 充足率のような閾値なし指標は分離の悪化を検出できない。**分布の分離度**を見る
- 平均指標は不均衡下で多数派に支配され、**稀少・重要クラスの低下を隠す**。PR-AUC / F1 を使う
  ([Galileo](https://galileo.ai/blog/f1-score-ai-evaluation-precision-recall))
- 抽出は「**省略 / 捏造 / 誤り**」をフィールド単位で分けて集計する。単一の precision/recall に
  潰すと所在が分からない ([ExtractBench](https://arxiv.org/html/2602.12247v2))

## 回帰検出の統計

- NLP 専用の検定ガイド: [Dror et al. ACL 2018](https://aclanthology.org/P18-1128/)
  (ペアードブートストラップ / permutation test の使い分け)
- **paired 設計 (McNemar) は独立 2 群比較より桁違いに少ない標本で足りる** — 2pt 差の検出に
  独立設計で約 6,300 例/群に対し、ペアードなら数百例規模
  ([dev.to](https://dev.to/gabrielanhaia/eval-set-sizing-the-statistical-power-math-behind-llm-ab-tests-4gpc))
- 稀少クラスの区間推定は **Wilson score** が小標本で最良。n<5 では区間推定自体を諦め
  生の混同行列で報告する ([arXiv:2309.14621](https://arxiv.org/pdf/2309.14621))

## LLM-as-a-judge のバイアス

位置バイアス / 冗長性バイアス / **自己選好バイアス**の 3 種が繰り返し確認されている。
自己選好は「審査者は困惑度の低い = 自分が生成しやすい文を系統的に高評価する」ことに起因
([arXiv:2410.21819](https://arxiv.org/abs/2410.21819))。
→ **生成モデルと同系統のモデルを審査に使わない**。

## 評価セットの汚染と経年劣化

- 言い換え・翻訳による汚染は標準的な除染をすり抜ける ([LessLeak-Bench](https://arxiv.org/html/2502.06215v1))
- **SFT データ自体が評価セットを再暗記させる**リスク ([arXiv:2601.06103](https://arxiv.org/pdf/2601.06103))
  → 手元で goldset 86 件を学習から除外したのは正しい措置
- ⚠ **凍結セットのサイレント陳腐化**: 本番の入力分布が動くと代表性を失う
  ([Galileo](https://galileo.ai/blog/beyond-golden-datasets-static-evals-failures))。
  9月3日に「保存済みラベルは現在の体制を代表しない (一致 40%)」を実測したのと同じ現象

## ⭐⭐ 39 / 86 / 150 件で何が言えるか (検出力)

> 以下は上記手法を今回の規模に当てはめた試算で、**数値そのものに出典があるわけではない**。

| セット | 言えること |
|---|---|
| **39 件** (事象ニュース) | ⚠ **実質スモークテスト**。半数近くが劣化する壊滅的回帰しか検出できない |
| **86 件** (goldset) | 中程度の系統的偏りなら見える。⚠ 稀少クラスには無力 |
| **150 件** (triage) | 全体傾向の統計判定にようやく現実的。不一致ペアが 24 件程度あれば偏りを検出可 |

⭐⭐ **どのサイズでも「1 件の見逃しが致命的」という CTI の要件には統計的検出力では対応できない。**
必要な設計変更は 3 つ:

1. 重要クラスを**層化オーバーサンプルした全数レビュー用サブセット**を別立てにする
2. **揺らぎの床を毎回更新**する (複数回実行のブートストラップ)
3. ⭐ **有意性ではなく「重要クラスの悪化が 1 件でも出たら人手レビュー」という決定論的ゲート**を併用

3 番は、この repo が既に持つ「関門」の思想そのもの。**統計に頼らず構造で止める**。

## 手元の実測との対応

| 実測 | 文献 |
|---|---|
| 自由文の一致率は同一設定でも 0-6% | Dror et al. の「確率的出力由来のノイズ」。**実測揺らぎを帰無分布に使う方が信頼できる** |
| triage の →low 31 件 | ⚠ 平均指標 (Sonnet 一致 70.7%) では見えない。**全数レビューが要る** |
| goldset 86 件を学習から除外 | 汚染対策として正しい |
