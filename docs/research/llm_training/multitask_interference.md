# 多タスク SFT の干渉と混合比 (調査: 2026-09-05)

> ⚠ 出典は調査時に収集したもので、**本文の主張を筆者が独立に再検証したものではない**。
> 引用する際は一次情報に当たること。

## 1. 干渉のメカニズム

負の転移の標準的説明は **共有パラメータへの勾配衝突**。BADIT は
"conflicting gradients from different task data over shared LLM parameters" と定式化し、
15 タスクの活性化解析で大多数のパラメータが複数タスクで同時に活性化することを示した
([arXiv:2605.05676](https://arxiv.org/html/2605.05676v1))。LoRA では低ランク制約が
「多様なタスク要求を収容する最適化空間の容量」を狭め、干渉を悪化させるとされる
([LoRI, arXiv:2504.07448](https://arxiv.org/html/2504.07448))。

⚠ **「出力の長さ・冗長性の要求が異なるタスクの混合」を直接扱った論文は見つからなかった。**
近い機序として、構造化出力制約と内容生成の目標が「もつれる」ことで品質を損ない、
フォーマット遵守を別モジュールへ分離すると回復するという報告がある
([arXiv:2510.03595](https://arxiv.org/abs/2510.03595))。**手元の観測 (簡潔な分類・抽出が
丁寧な生成の作法を押し流す) はこの機序の一種として整合的だが、直接の実証は無い。推測。**

タスクが近ければ逆にシナジーも出る (金融 7 タスク + 汎用指示の混合で全タスク改善、
[arXiv:2410.01109](https://arxiv.org/html/2410.01109v1))。一方、単一タスク専門モデルが
300+ タスクの多タスクモデルを未見タスクで上回る報告もある
([Jang et al. 2023, arXiv:2302.03202](https://arxiv.org/abs/2302.03202))。
**干渉の有無はタスク間の類似性に強く依存する。**

## 2. 混合比の効果

T5 は「**均等混合は失敗しやすい**」「サイズ比例 (上限キャップつき) が妥当な既定値」
「温度スケーリングが単一ノブの代替」と報告
([arXiv:1910.10683](https://arxiv.org/abs/1910.10683))。

系統的手法: DoReMi (小型プロキシで Group DRO により領域重みを決定、8B で平均 +6.5pt・
2.6 倍高速収束、[arXiv:2305.10429](https://arxiv.org/abs/2305.10429))、CMR スケーリング則
([arXiv:2407.17467](https://arxiv.org/abs/2407.17467))、混合比の関数として損失を予測する
加法則・結合則 (MRE 0.3-4.5%、[arXiv:2507.09404](https://arxiv.org/html/2507.09404))。
⚠ **これらは主に事前学習のドメイン混合が対象で、SFT の少数タスク混合への外挿は実証が薄い。**

## 3. タスクごとの必要データ量 — 非対称性

LIMA は 1000 例で 65B を整合させ、"Superficial Alignment Hypothesis" (能力は事前学習で
獲得済みで、alignment は応答フォーマットの部分分布を教えるだけ) を提示
([arXiv:2305.11206](https://arxiv.org/abs/2305.11206))。Instruction Diversity も
「タスクあたりの事例数は少数で飽和する一方、タスクの多様性を増やす効果は大きい」と報告
([arXiv:2402.10891](https://arxiv.org/abs/2402.10891))。

⭐ **「形式・出力契約」は少データで学べる/上書きされやすい、「判断・丁寧さを要する生成能力」は
より多く一貫した信号を要する** — この非対称性は複数の独立した論文で収束しており、
実証は比較的強い。逆に言えば、簡潔タスクの「型」は数百例で過学習域に入り、
混合比を上げるほど他タスクへの侵食力が相対的に強まる。

## 4. LoRA の容量と干渉

Capacity and Redundancy Trade-offs は理論的に「共有ボトルネックの容量がタスク数に比例して
増えない限り、タスク数を増やすとどこかのタスクが予測信号を失う (C_s ≥ T·b)」を証明
([arXiv:2607.16554](https://arxiv.org/html/2607.16554))。同論文の実験では**ランクを増やすだけでは
単調に改善せず**、タスクをクラスタ化して専用容量を割り当てる方が固定予算下で有利だった。

補足: LoRA はフル FT より対象タスクの学習量は少ないが、**対象外タスクの保持 (忘却耐性) は
優れる** ([Biderman et al. 2024, TMLR, arXiv:2405.09673](https://arxiv.org/abs/2405.09673))。
低容量が学習を抑えることと汎化崩壊を防ぐことは表裏一体。

## 5. 緩和策

| 手法 | 効果量 | 実証の強さ |
|---|---|---|
| 温度スケーリング / 比率調整 | T5 で確立 | 強い・低コスト |
| PCGrad / CAGrad (勾配衝突の射影) | 画像・RL 中心 | ⚠ **LLM の LoRA-SFT での実証は薄い** |
| LoRI (A 固定・タスク別スパースマスク) | HumanEval で LoRA 比 +17.3%・訓練パラメータ 95% 減 | [arXiv:2504.07448](https://arxiv.org/html/2504.07448) |
| BADIT (直交 LoRA 専門家分解) | Rouge 54.33→55.87、逐次学習の忘却 8.96%→6.95% | [arXiv:2605.05676](https://arxiv.org/html/2605.05676v1) |
| 単一タスク専門 + マージ/ルーティング | Jang et al. / [arXiv:2411.14064](https://arxiv.org/pdf/2411.14064) | 中 |
| リプレイ 1-10% | ⚠ **最適比率のコンセンサス無し** (CT0 は 1%、他は 10%) | 文脈依存 |

## 6. 手元の実測との対応

| 実測 (2026-09-04〜05) | 文献との整合 |
|---|---|
| 混合 32:35:33 で生成タスクが base 以下に悪化 | T5 の「均等混合は失敗しやすい」に該当。⭐ **比率自体が疑わしい既定パターン** |
| 契約 (空欄・重複) は 150 反復で学習、能力は 700 反復でも教師の 39% | LIMA / Instruction Diversity の非対称性と**強く整合** |
| LoRA 8 層 0.35% で 3 課題 | Capacity-Redundancy の `C_s ≥ T·b` が満たされにくい典型 |
| 分類・抽出は少量で改善済み (飽和の兆候) | 簡潔タスクは数百例で飽和 → **削って生成に配分するのが理論的に正しい** |

⭐ **v3 (事象ニュース 50% へ増量、分類・抽出を 360 件へ削減) は文献の示唆と一致する方向。**

⚠ ただし「出力長・冗長性の異なるタスクの混合が干渉を生む」という観測そのものを直接
検証した論文は無い。**機序として整合的だが未実証**として扱う。

## 7. v3 が失敗した場合の候補 (文献が支持する順)

1. **事象ニュースだけ独立 LoRA、分類・抽出は共有 LoRA** — 出力契約が近いもの同士を共有する
   容量配分。Capacity-Redundancy と Jang et al. の双方が支持
2. **LoRI / BADIT 型のタスク別マスク** — 実装コストは高いが直接的
3. ランクを機械的に上げる — ⚠ **単調に改善しないと報告されている**。優先度は低い

**この env は 2026-07-08 に撤去済みで実在しない** (モデル割当の SSoT は DB)。
外部調査の結果をこの repo の現況と突き合わせずに適用しないこと。
