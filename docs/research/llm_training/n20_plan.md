## 3. 翻訳・MITRE 和訳を n20 に取り込む

### 3.1 なぜ n 系か・何が危険か

- 翻訳は自由文。s 系 (JSON 課題) に入れると崩れる (10-02: 637 件、s21 が `{"原文": "訳文"}` と原文の写しを混ぜた)。n19 も翻訳 5 件中 4 件が同じ崩れ。**n 系は長文の自由文を学習している (事象 bluf・Spotlight outlook) が、出力の殻は JSON** なので、翻訳を学習していない n19 でも崩れた = **学習しないと崩れる**。
- **今の翻訳 (`kuebiko-sft:26b` = N1) は崩れていない**: N1 は n 系の初版で、8 層・4bit QLoRA という弱い LoRA。n20 (bf16・30 層・rank 64) は JSON 偏りが強く、n19b も崩れた。つまり今の翻訳が崩れないのは LoRA が弱いためで、**n20 は翻訳を学習しないと崩れる前提**で設計する。
- `kuebiko-sft:26b` (N1) の化け (`c2c_x_report.md` §3.1): (a) Gemma4 26B Q4_K_M 自体が低頻度トークン (固有名詞・数字・レア漢字) に弱い (公式 `gemma4:26b` も 50% の試行で化ける)、(b) 自前変換 (4bit → dequantize → 再 4bit) が決定論的な誤りを固定する (再現率 72.5% 対 50.0%)。
  **n20 は bf16 学習 → int8 取込み**なので、(b) の二重量子化は無い。(a) が減るかは**未測定** (推測: int8 で低頻度トークンの精度は上がる)。
- 翻訳の現状 (出典: `A2_shadow_review_report.md` §5・`c2c_x_report.md` §1・`C2c`): **17.1% と 30.7% は同じ Opus 監査 (`c2c_translate_audit_v1.jsonl`、150 件) の分母違い** = 境界でない 105 件中 18 件 (17.1%、主指標) / 全 150 件中 46 件 (30.7%、境界込み、副指標)。46 件のうち化けのみ 16 件 (34.8%)・意味の誤訳のみ 18 件 (39.1%)。
  `TRANSLATE_FIDELITY_GATE=ident` の発火 14/680 記事 = 2.1%。`body_backlog_translate_failed` 1,310 件のうち**原文の写し 1,074 (917+133+24)・JSON 混入 70**。

### 3.4 翻訳の評価・合格線・撤退条件

**2 腕の学習 (推奨で決定 10-15)**: 翻訳を足したときの干渉 (n17m は長文 2 課題で干渉、30 層で 3 課題目で再発) を切り分ける腕がない問題への手当て。**同じ夜に n20a (翻訳・和訳なし) と n20b (あり、翻訳・和訳 ≤1,200 例 = 25% 以下、露出 1 回) を学習**し、事象・Spotlight・総括の差で干渉を n20b の翻訳分に帰属する (追加 約 $30)。件数の計算: 事象 1,800 + Spotlight 600 + 総括 330 + 深掘り 900 = 3,630 (露出込み)。翻訳 1,400〜2,800 を足す案 (露出 1〜2 回) は 5,030〜6,430 で翻訳比率 28〜44% と目標 25% を超えるため採らない。

**合格 (両腕を同じ夜に訳し直した現行 `kuebiko-sft:26b` との比較)**:
- **主指標** = 境界を除く重い問題 (現行の報告値 18/105 = 17.1%)、**副指標** = 境界込み (46/150 = 30.7%)。**合格は両方とも現行以下** (目標 ≤5% は別枠で追う)。

## 5. 既存の方針 (守ること)

- **学習と本番の入力の形を揃える**。Ollama の `prompt_eval_count` と学習の入力長が一致すること。空の思考欄を付けない。長い実例・全課題で確かめる (09-27 の教訓)。
- **教師から除く**: ナビ残骸の入力・契約外の欄・当て推量の ATT&CK・格上げ (同じアクター → 同一キャンペーン)・出典番号の帰属ずれ。字数で機械的に切らない。
- 文字列の `maxLength` を入れない (暴走を誘発)。repetition penalty は使わない。生成後に決定論で切る。
- 関門は維持: `evidence_citation_gate`・`identifier_check` (Spotlight の固有名詞)・`TRANSLATE_FIDELITY_GATE`・`broken_translation_reason`。
- 中華系 denylist は変わらず 3 層で効く。学習の素のモデルは Gemma 4 系。

## 6. データの偏りを作らない

1. 線つき / 線なしの両方の入力で出力品質が崩れないこと (フラグを戻したとき)。半々で学習する。
2. 領域に偏らせない (10-02 方針): 事象の種類 (APT・ランサム・脆弱性・地政学・政策) を層化。
3. 翻訳は言語・長さ・識別子の密度で層化。日本語の原文 (翻訳不要) は**学習に入れない**が、本番で誤って届いた場合に原文を写さない例を少数 (推測: 20 件) 含める — §3.2-1 の分類で必要性を判断。
4. 学習前に課題別・領域別の分布表を作る (s24_plan §6-4 と同様)。

## 9. リスクと対策

- **翻訳が JSON に崩れる**: n19 の前例 (N1 は弱い LoRA だったので崩れていない)。対策 = プレーンテキストの殻・`[task: translate]`・学習中の実物確認 (毎エポック終了時に 100 chunk)・撤退条件 (§3.4、撤退すると公式 26B が 3 本目として残る)。
- **多課題の干渉**: 長文 2 課題の混合で干渉した前例 (n17m、n18、30 層でも 3 課題目で再発)。事象・Spotlight・状況総括は n19 で統合済み (干渉なし)。**深掘り・翻訳を足した干渉は n20a / n20b の 2 腕で切り分ける** (§3.4)。
- **本番の線の実装が間に合わない**: 線つきの教師は「実装が先」。間に合わなければ線なしだけで学習し、線つきは次の学習へ送る (n20 の合否に線を含めない)。
- **教師の癖を写す**: 根拠なし 2.2/例などの癖。根拠監査・書き直しを済ませた教師だけを使う。
- **切替の波及**: 事象ニュースの要点が下流 (群化・kind) に流れないか shadow 比較。翻訳は `body_ja` の再翻訳キューへの影響 (保存済みの '' は `UPDATE articles SET body_ja=NULL` で再翻訳)。
- **許可リストの更新漏れ**: `PREFIX_TRAINED_MODELS` に `kuebiko-sft:n20` を足す。`UNTRAINED_STEPS` の n19 の項は n20 には作らない (深掘りも学習済み)。翻訳・和訳の `TASK_MARKERS` を足す。
- **クラウド**: 学習結果は S3 窓口経由で分割して書き出す (n19b の 524 打ち切り。`pod_run.sh` の修正は f5c6f720 (09-29) で**済み**)。RunPod H200/B200、1 本 約 5〜6 時間・約 $30 (推測、n19 は 3〜5 時間・約 $25)。n20a・n20b の 2 本で 約 $60。
- **翻訳を n20 に寄せたときの運用**: 事象ニュース (毎時、600 秒) と翻訳が `NUM_PARALLEL=1` で順番待ちになる → 運用の段で翻訳の処理量を実測する。
- **guard の追加**: 翻訳の教師は 10-03 より前の記事と 150 件を除く窓から取る (§7.1)。

## 10. 手順と概算

1. **N0 事前 (GPU 不要、1〜2 日)**: **済み** = 教師の根拠監査・書き直し (§2)、本番の n19 = n19b、状況総括の使用実態 (使われている)。**残り** = 翻訳失敗 1,074 件の分類 (§3.2)・Opus が拒否した窓の洗い出し・再監査の入力の描き直し。

3. **N2 線の受け皿の実装 (本番、フラグ off)**: 事象ニュースの context 専用欄 (または出典番号の拡張)・深掘りの線。テストとセット。
