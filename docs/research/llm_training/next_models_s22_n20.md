## 4. 新しい PIR 機能・GraphRAG とモデルの位置付け

### 原則 (これまでの実測から)
1. **数える・集約する・グラフをたどるのは決定論、言葉で判定し書くのが LLM**。散文で集約値を渡しても
   ACH は採点しない (09-16、観測系の仮説が 1 つも採点されなかった) — **構造 (欄) だけが効く**
2. 集約は LLM の結論を置き換えず、**確度の上限**として効かせる (`aggregate_confidence_cap` と同じ思想)
3. 関係 (線) は高精度の層からだけ作る。LLM の生タグ・言及・共起から作った線は雑音 (09-26 の KG 検証)
4. 因果は推論させない (地政学相関の原則)。LLM は**与えられた線の範囲で**書く

### 常設情報要求 (standing questions、9 問) の ACH
- 答えは「直接の腕 (稀だが決定的) + 間接の腕 (蓄積で意味を持つ)」の 2 本から組み立てる
- s21 は昼の ACH (記事の抜粋 = 証拠項目) で学習しているが、**集約シグナル (構成比・平常からの変化) を
  証拠として採点する形は学習していない**。本番の入力にその欄を足すなら、教師データも同じ欄で作る
- 役割: **s22 が「構造化された証拠 (直接・間接・集約) を仮説ごとに採点する」**。数値の算出はしない

### SIR の回答の文章化 (PIR への答え)
- 台帳・常設の問いの判定を、読み手向けの答えに書く面 (`render_pir_answer_prototype.py`)。
  製品化するなら n20 の新しい課題。**判定は s22 (ACH)、文章化は n20** と分ける

### GraphRAG
- 期待する使い方: 状況総括・ACH・Spotlight の根拠を、事象→指標→事象の線 (メタパス:
  アクター→CVE→製品、組織→業種/国) でたどって集める
- **効果は未測定**。GraphRAG が勝つのは多段・集約の問いだけ (GraphRAG-Bench)。先に、
  **学習なしで Opus に「現行の入力」と「グラフでたどった根拠つきの入力」の両方で書かせて対読する**
  (外部枠のみ、GPU 不要)。効くと分かってから、その入力の形で教師を作り直す
- モデルの役割: 線を**作らない・推論しない**。与えられた線 (出典つき) を引用して書く。
  学習データの入力には、線ごとに出典と種類 (役割・裏付けの強さ) の欄を持たせる

### 学習の前後の手順 (毎回)
1. 学習の入力長が Ollama の prompt_eval_count と一致すること (長い実例・全課題)
2. 学習の結果はサーバが S3 経由で分割して書き出す (§2)

4. 評価は本番のスキーマ・長い生成・実記事で。**数字と中身の両方**で判断する

| G2 取り方 | 共通の取得モジュール (src/graph/)・ハブの抑制 (1 アクター 3 本)・**候補外の同じ事象への線は 1 行にまとめる** (多産な国で 1 事象が 12 行を占めていた)・呼び手が優先したい指標を先に (配線はまだ) | 済 |
| G3 線の種類 | Opus 5.5 盲検 各 20 組 (`data/eval/graphrag_line_audit_v1.jsonl`): **同じ帰属国 17/20 正しい (役に立つ 15) → 開く** (候補外の事象だけ・節全体で 5 本・誤りは帰属の無い事象に付いた国 1 件由来) / 同じ業種・国 13/20 (報告機関の国を被害国に) / 珍しい道具 3/20 (触れただけ・本文に無い道具を「使った」と抽出) → 後の 2 つは抽出を直すまで出さない | 済 |
| G4 対読 | 状況総括・事象ニュースで線なし / 線つきを凍結窓で比べる (`scripts/graphrag_{synthesis,eventnews}_compare.py`、Opus 盲検 → ローカル n19 / s21)。Spotlight は G1 の形で測り直す | Opus 済 (下) |

**G4 の結果 (2026-10-08、書き手・審判とも Opus 5.5、凍結 15 窓、盲検。線つき : 線なし : 同等)**
| 課題 | 総合 | つながり | 根拠 | 見通し | 格上げ |
|---|---|---|---|---|---|
| 状況総括 | **14 : 1** | 14 : 0 : 1 | 2 : 3 : 10 | 6 : 6 : 3 | 0 / 15 |
| 事象ニュース | **13 : 2** | 12 : 0 : 3 | 3 : 6 : 6 | 11 : 2 : 2 | 0 / 15 |
- 格上げはゼロ。「同一キャンペーン」は線つき版にだけ出たが**全件が否定** (「…の根拠にはならない」)。
  格上げ語の機械検出は否定も数えていたので、直後の否定・留保を除く形に直した (`_asserted`)
- **事象ニュースの根拠の減点の型**: ①線から引いた過去の事象を、候補記事の出典番号 (source_index) に
  帰属させる ②線の被害組織から「○○への掲載が続いている」と一般化する。①は形の問題 —
  事象ニュースの事実は必ず候補記事を出典に持つので、線の事象を引く受け皿が無い。
  **本番に入れる前に、線を引用できる番号 (または context 専用の欄) を作る**
- 状況総括は線のほぼ全部が「同じアクター」(ランサム系) で、出力の多くが凡例の言い換えを繰り返す
  (「攻撃者名の共有を示すにすぎず…」)。つながりの勝ちは文脈の追加で、根拠は悪化しない
- 線の質: Lukoil の資産売却の事象に Qilin の線が付いた例 (主題の誤り)。Opus は使わなかった
- 次: ローカル (n19) で同じ窓を書かせ、格上げと出典のずれを測る。n21 の教師は線つき入力で作る
評価に足すもの (§8.4 と同じ): 線の格上げ率、誤った線の採用率、線なしの入力で崩れないこと。

#### 9.4.1 合議のラベルで教師の質を担保する条件 (2026-10-03、利用者「慎重に検討」)
RunPod は教師づくりに使わない (利用者判断: 学習データの作成にお金をかけない)。手元のモデルの合議で Opus を
減らす場合の危険と採用の条件:
- 危険: 同じ誤りの共有 / やさしい例への偏り / 共通の偏りの学習 (領域の偏り) / 学習の系統による循環 / ラベルが合っても理由の文は保証されない
- 条件:
  | 条件 | 内容 |
  |---|---|
  | 投票役 | 学習の系統 (s21・s22) を外し、系統の違うモデル (gpt-oss-120b・K2 Horizon 36B-A4B・Gemma 4 31B) だけ |
  | 合議で採った分の正しさ | 調整に使っていない正解集で、Opus どうしの一致 (5.5 中 vs 高 38/40 = 95%) と同じ水準 |
  | 重い取り違え | 合議で採った分の中で 0 件 (high → low、S3 → S1) |
  | 境界の記事 | 合議で決めず必ず Opus |
  | 分布 | 合議で採った分のラベル分布が Opus の正解の分布とずれない (課題・クラスごと) |
  | 理由の文 | 一部を Opus の盲検で確認。弱ければラベルだけ使い、理由は Opus |
  | 運用中 | 合議で採った分の 5〜10% を Opus で抜き取り、ずれが基準を超えたら止める |
  | 最後の確かめ | 小さな課題 1 つで、Opus だけの教師と合議を混ぜた教師で学習を比べる |
- 長文生成の課題は合議が使えないので対象外 (Opus の枠を優先して回す)
- **判定 (2026-10-04、条件を満たさない → 教師は Opus 5.5 だけ)**: 正解 = Opus 5.5 で付け直した triage 150 件 (v3)。
  | 候補 | triage (境界を除く) | 深刻さ | 軸の平均 | 秒/件 |
  |---|---|---|---|---|
  | gpt-oss-120b 中 | 89% (47/53) | 82% | 69% | 9 |
  | gpt-oss-120b 高 (半分) | 96% (24/25) | 80% | 68% | 23 |
  | K2 Horizon 36B-A4B 考えなし | 81% | 87% | 67% | 6 |
  | (参考) 素の 26B | 69% | 82% | 61% | 3 |
  - 合議 (系統の違う gpt-oss 中 × K2): 一致 81%、一致分の正しさ 94% (44/47)・重い取り違え 0。だが一致分の
    分布が偏る (high 5 件中 2・low 18 件中 11 しか残らない = やさしい medium に寄る) ので「分布」の条件を
    満たさない。gpt-oss の中×高・中×低は 95〜96% だが同じモデルどうしで「同じ誤りの共有」に当たる
  - 境界は Opus の正解で 55% (82/150) あり、合議で節約できるのは境界でない triage だけ。深刻さ・軸は
    候補が 80% 台・60% 台で教師にならない (軸は s22 の 84% が最高)
  - 標本が小さい (25〜58 件) ので、条件の水準に近い gpt-oss 高は、Opus の枠が足りなくなったときの再検討候補に残す
- 確かめるための正解集づくりにも Opus を使うので、節約量はその分を差し引いて見積もる
