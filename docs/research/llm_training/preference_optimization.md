# SFT 後段の選好最適化 (DPO 系) (調査: 2026-09-05)

> ⚠ 出典は調査時に収集したもの。筆者が独立に再検証したものではない。

## 手法の選択基準

| 手法 | データ形式 | 参照モデル | 特徴 |
|---|---|---|---|
| [DPO](https://arxiv.org/abs/2305.18290) | ペア | 要 (メモリ 2 倍) | 標準。**選好差が自明だと KL 正則化が効かず過学習** |
| [IPO](https://arxiv.org/abs/2310.12036) | ペア | 要 | 二乗誤差ベースの有界目的。DPO の過最適化への対処 |
| [KTO](https://arxiv.org/abs/2402.01306) | **非ペア** (二値ラベル) | 要 | desirable を 90% 間引いても DPO 同等以上 |
| [ORPO](https://arxiv.org/abs/2403.07691) | ペア | **不要** | SFT 損失にオッズ比ペナルティを足すだけ |
| [SimPO](https://arxiv.org/abs/2405.14734) | ペア | **不要** | 長さ正規化。**外すと「長く反復的な出力」に劣化**とアブレーションで確認 |

## ⭐ on-policy が効く理由は「被覆でも質でもなくサンプリングそのもの」

DeepMind の実証 ([arXiv:2405.08448](https://arxiv.org/abs/2405.08448)): 同じ選好データでも
オンラインがオフラインを一貫して上回り、原因は**オンポリシー・サンプリングそのもの**。
また「成功する手法は例外なく**悪い応答の確率を下げる負の勾配**を持つ」— **SFT にはこの機構が無い**。

→ 手元の材料 (SFT 済みモデル自身の欠陥出力を rejected にする) は、**文献が最も推す形**。

## ⭐⭐ 重複列挙に最も近い実例

Liquid AI の **Antidoom / FTPO** ([blog](https://www.liquid.ai/blog/antidoom)): 同一トークン列を
無限反復する "doom loop" に対し、通常の DPO ではなくループ開始トークンを狙い撃ちする
専用手法で **loop 率 10.2%→1.4%** (Qwen3.5-4B では 22.9%→1%)。

**「局所的で自己強化的な悪癖は SFT の追加データだけでは根治しにくく、コントラスト学習が要る」**
という、手元の重複列挙 (56.8%) に極めて近い実例。
⚠ ただし著者自身が「構造化出力への一般化は未検証」と明言。

⚠ `"null"` プレースホルダについては**この具体パターンを扱った論文は見つからなかった**。
一般原理からの類推のみ。

## ⚠ 副作用 — 素の DPO は今回の欠陥を悪化させうる

- **多様性崩壊**は主に DPO 由来で SFT では起きない ([arXiv:2603.24124](https://arxiv.org/html/2603.24124v1))
- **長さバイアス**: DPO の暗黙報酬は長さと相関し、SFT 比 +40〜45% の出力長増加
  ([arXiv:2406.10957](https://arxiv.org/html/2406.10957))
- ⭐⭐ SimPO のアブレーションで「**長さ正規化を外すと長く反復的な出力になる**」
  → **素の DPO を不用意に使うと、直したい重複列挙をむしろ悪化させるリスク**
- 「null vs 正しい値」のような**自明なペア**は、IPO 論文が指摘する過最適化条件にちょうど該当

## 実装 — mlx-lm 本体には無い

確認済み: 公式 mlx-lm に DPO トレーナーは無い。追加 PR
([mlx-lm#7](https://github.com/ml-explore/mlx-lm/pull/7)) はメンテナにより
**マージされず 2025-05-18 にクローズ**。

代替: [mlx-lm-lora](https://github.com/Goekdeniz-Guelmez/mlx-lm-lora) (個人メンテナ・MIT・
PyPI v3.1.2) が DPO/CPO/ORPO/GRPO/Online DPO/PPO **および FTPO まで実装済み**。
⚠ 単独メンテナのコミュニティ製。**投入前に TRL 実装との突合せで健全性検証が必要**。

## 判断: やる価値はある。ただし最小リスク版で

1. 損失は **IPO を既定** (DPO と同一データで損失フラグのみ変更、過最適化に強い)。
   重複が悪化するなら **SimPO** (長さ正規化) へ
2. **低 beta・少エポック (1-2)・held-out で早期終了** — 小データ + 自明ペアは過学習の典型
3. 重複列挙には **FTPO を安価な副実験として先に試す**価値がある
4. ⭐ **`"null"` のような出力契約違反は、選好最適化で頻度を下げられても根絶は保証されない。**
   決定論的な関門 (この repo が既に持つ検査) は選好最適化と**独立に維持する**

## 手元の材料との対応

| 材料 | 評価 |
|---|---|
| SFT 自身の欠陥出力 × 正解 (同一プロンプト) | ⭐ on-policy = 文献が最も推す形 |
| 数百対 | 欠陥が 1-2 種に絞られた狭い問題なら妥当な範囲 (⚠ 直接の実証は無く類推) |
| 関門に落ちた草稿 × 通った版 | 客観基準でラベル済み。ORPO/IPO に使える |
