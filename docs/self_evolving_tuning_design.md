# 自己進化チューニングループ (較正格子) 設計

作成: 2026-08-21。LLM チューニングの自動化検討 (retrieval few-shot / 正解ラベル整備 /
自己進化ループの議論) の帰結をまとめた全体設計。**実装前の合意用文書** — 着手順・
コンポーネント境界・不変条件をここで固定する。

---

## 1. 目的と、自動化しないものの宣言

**目的**: プロンプト (rubric) チューニングの「測る → 例を良くする → 変更を試す → 戻す」
のループから人手作業を可能な限り除き、人間の関与を以下の 2 点に濃縮する:

1. **目的の定義** (何が high か・PIR — 真偽でなく準拠点の問題)
2. **fail-closed の拒否権** (証拠付き提案の承認 / パネルすら割れる係争の裁定)

**自動化しない理由が原理的なもの (3 つの壁)**:

- **壁 1 — 相関した盲点**: 全 LLM は重なった学習分布を共有し、新奇事象・ローカル文脈・
  稀少クラスで誤りが相関する。多様パネルは壁を細らせるが消せない。かつ本ツールの
  致命的失敗 (稀少 high の取りこぼし) はまさにこの領域にある。
- **壁 2 — 規準の問題**: 重要性の定義はドクトリンの事実であり、投票では到達できない。
- **壁 3 — 合意 Goodhart**: パネル合意率を最適化目標にすると、システムは「モデル間
  コンセンサス = Web の平均事前分布」へドリフトする。合意は routing にのみ使い、
  **報酬 (最適化の目標関数) には決して使わない**。

**人間も oracle ではない** (バッチ承認事故 07-26、測定誤りの実績)。人間を残す根拠は
正確性ではなく: ①誤りの脱相関 (Web コーパス外の判定器) ②帰結の非対称 (veto の誤りは
回復可能、auto-apply の誤りは複利) ③責任の非委譲性。**人間の裁定も較正対象とする**
(遅延正解による事後監査)。

## 2. 設計原則 (既存原則との接続)

| 原則 | 本設計での適用 |
|---|---|
| 指示より決定論的関門 | 適用 (apply) は人承認のみ・rollback だけ無人、を code で強制 |
| 承認キュー 3 原則 (起票→レビュー UI→承認=適用の終端保証) | 提案・係争の両キューに適用 |
| 成功も記録する | パネル裁定・人間裁定・自動採用のすべてに来歴と結果を永続化 |
| 対照群なしでは何も言えない | 全評価は 基準1/基準2(対照)/変種 の 3 者比較 (gold set 既設) |
| 母集団の反転 > フィルタ追加 | ラベルは「LLM 出力の採点」でなく「外部正解との突合」を起点に定義 |
| ICD 203 (確度の規律) | 運用者自身の裁定にも適用 (override の事後成績を可視化) |

## 3. 全体アーキテクチャ: 較正格子

正しさはどの単一ノードにも宿らない。強い順に並ぶ「すべて誤りうる証拠源」が、
重なる領域で相互較正する格子として全体を構成する。

```
[E0 決定論的事実]  feed 帰属 (犯行声明)・引用実在チェック・schema/辞書ゲート
      │  (最強。ここだけが無条件の錨)
[E1 遅延正解]      後日の MITRE 帰属確定・dedup クラスタでの続報整合・
      │            PIR 事後マッチ・訂正報道 — 「未来が過去の判定を裁く」
[E2 多様パネル]    異系統モデル群 + 条件付け (盲検再判定・摂動安定・含意分解)
      │            E0/E1 と重なる層で 合意度×実正解 の較正曲線を常時測定
[E3 人間裁定]      パネル分裂のみ着弾。裁定は E1 で事後監査 (人間も較正される)
[E4 ドクトリン]    PIR・rubric の意図。機械は「誤り」を問えないが
                   「内部不整合」「現実との乖離」(PIR 逆転検出の実例) は指摘する
```

**確信度ルーティング** (格子の出力):
- 高確信帯 (較正曲線で実測された帯) → 自動採用 → ラベル化・few-shot プール供給
- パネル分裂・低確信 → E3 (人間キュー) へ
- E1 未到着で確定不能 → 「係争中」として保持 (即断しない)

## 4. コンポーネント設計

### C1: 遅延正解の収穫 (格子の燃料) — 最初に作る
- 週次ジョブ。「当時の判定 vs 後日確定した事実」を突合し `tuning_labels` に書く。
- 初期ソース: ①feed 帰属×ニュース記事 (victim_org ±5 日突合 — 実証済み手法) ②MITRE
  週次同期での帰属確定 ③dedup クラスタ内の判定不整合 ④PIR 事後マッチと importance の乖離。
- テーブル: `tuning_labels(id, article_id, field, label_value, source(E0..E3), strength,
  arrived_at, provenance, superseded_by)`。**新列 3 点セット規約に従い、消費者 (C3/C8) を
  同時に実装**する。

### C2: 多様パネル裁定
- 陪審: Gemma 26B (現用) + Llama 3.1 8B (安価な異議者) + 外部 LLM (分裂時の上級監査、
  ティア明示割当 + 予算 cap)。§4 denylist 準拠はモデルティア既存 3 層防御に乗る。
- 条件付け: 盲検 (元判定を見せず証拠のみ) / 摂動再判定 (言い換え安定性) / 含意分解
  (根拠引用の実在は E0 チェック、引用→主張の含意のみ問う)。
- **呼び出し点は 2 つだけ**: ①raw 不一致・係争の裁定 ②rubric 変種の評価。
  per-article には使わない (コスト不変条件 §6)。

### C3: 較正層
- E0/E1 が存在する層で「パネル合意パターン × 実正解率」の較正曲線を層別に維持。
- 外挿 (正解のない層への適用) は**明示された仮定**として文書化し、ドリフト番兵
  (合意率分布の変化検知) を常設監査に登録する。

### C4: 確信度ルーティング (§3 のとおり)

### C5: 人間裁定キュー + 人間の較正
- 着弾はパネル分裂のみ (全不一致の 1 桁減を見込む)。1 日 5 分 cap。
- 裁定環境の設計自体が精度変数: 証拠の提示・2 択化・バッチ承認の抑止 (07-26 教訓)。
- 人間裁定も E1 到着時に事後監査し、override 成績を可視化する。

### C6: 提案生成 + 自動評価
- LLM が不一致サンプルから rubric 改善案を起案 → gold set 3 者比較を自動実行 →
  「効果 X (揺らぎ床 ±Y)・回帰面ゼロ」の証拠付き提案としてキューへ。
- **適用は人承認のみ** (版履歴付き block 編集として — 層分け基盤に乗る)。

### C7: 自動 rollback 関門 (唯一の無人適用)
- cutover 後の週次指標が劣化したら該当プロンプトを前版へ自動復帰 + ops 通知。
- fail-closed 方向のみ無人、が本設計で唯一の自動適用。

### C8: few-shot プール管理 (retrieval few-shot の実体)
- 高確信ラベル付き事例を embedding 近傍検索 (dedup 用 arctic-embed2 基盤を流用) で
  k=2-3 件、composer の例示層へ code 所有の動的注入。
- 例に **rubric 版数を紐づけ**、版を跨いだら無効化 (旧基準を教えない)。
- 例プールにも層化を適用 (稀少クラスの偏り防止)。

## 5. ガバナンス不変条件 (違反 = 設計違反)

1. パネル合意は routing 専用。**最適化の目標関数に使わない** (壁 3)。
2. ループの報酬・合否判定は E0/E1 層のみに錨を打つ。
3. 前向き適用 (rubric 変更) は人承認のみ。無人適用は rollback (後ろ向き) だけ。
4. すべての裁定 (自動・パネル・人間) に来歴を残し、E1 で事後監査可能にする。
5. 評価は常に 3 者比較 (対照群必須)。
6. per-article のパネル呼び出し禁止 (LLM 時間予算の保護)。
7. モデル選定は §4 denylist / ティア 3 層防御に乗る。外部 LLM は明示割当 + 予算 cap。
8. **人間は加速材であって燃料ではない** (2026-08-21 追加、§12): すべての人間タッチ
   ポイントは無応答時の既定挙動 (保守側) と TTL を持ち、人間の非介在がループの進行を
   停止させない。事前の人承認を要求するのは前向き rubric 適用 (不変条件 3) のみで、
   それ以外の人間関与は事後 veto (非同期の拒否権) として設計する。
9. キューは必ず (a) TTL (b) 上限件数 (c) superseded 自動失効 を持つ。溜まり続ける
   キューを作らない (07-31 承認キュー全数調査で「気付かれず滞留」を実証済み)。

## 6. 段階的実装計画

| Phase | 内容 | 完了条件 |
|---|---|---|
| P1 | C1 遅延正解収穫 (①feed 突合 ②MITRE 確定 — §10.3) + 既存レビューの E3 producer 合流 (§11-A) + tuning_labels + 消費者としての簡易表示 | 週次でラベルが自動蓄積し、種別ごとの件数が UI で見える。人間が一切触らなくてもラベルが増え続ける (§12) |
| P2 | C6 後半 (gold set 3 者比較の cron 化) + C7 自動 rollback | rubric 変更の翌週に自動で合否が出て、劣化時に無人で戻る |
| P3 | C2 パネル + C3 較正曲線 (E0/E1 層で測定開始) | 合意度×正解率の曲線が層別に出る |
| P4 | C4 ルーティング + C5 人間キュー (裁定 UI) | 不一致の大半が自動裁定され、人にはパネル分裂のみ届く |
| P5 | C8 few-shot 注入 (judgment から) + C6 前半 (提案生成) | 3 者比較で few-shot の効果が測定され、証拠付き提案が届く |

各 Phase は独立にデプロイ可能・独立に rollback 可能とする。P1-P2 は既存部品の組合せで
小さく、P3 以降が新規性の中心。

## 7. リスクと未解決問題

- **外挿仮定の検証不能性**: 較正曲線の「正解のない層への転移」は原理的に検証できない。
  緩和はドリフト番兵と、稀少クラスを常に E3 (人間) 側へ倒す保守ルーティングのみ。
- **パネルのコスト/時間**: 分裂率が想定より高いと E3 が溢れる。P3 で実測してから
  P4 の閾値を決める (単発見積りを本番に外挿しない)。
- **ドクトリン変更時の較正リセット**: PIR/rubric の大改訂は較正曲線と few-shot 例の
  前提を壊す。版数紐づけで自動失効させるが、失効直後は自動採用帯が縮む (仕様)。
- **稀少クラスの標本不足**: high・日本標的の較正は標本が集まりにくい。層化と
  「不足層は自動化しない」の明示が必要。

## 8. 着手前に利用者の決定が要る事項

1. **外部 LLM (パネル上級監査) の使用範囲**: 記事本文が外部送信される。ティア明示
   割当の枠内だが、パネル用途への割当可否と月間予算 cap。
2. **裁定 UI の置き場**: 既存レビューキュー群 (承認 UI) への統合で良いか。
3. **P1 の遅延正解ソースの優先順**: 上記 4 種のうちどれから始めるか (推奨: ①feed 突合
   ②MITRE 確定 — いずれも決定論で実装が軽い)。

## 9. 終着点: この設計が向かう先 (2026-08-21 追記)

few-shot は終着点ではなく H1 の技法である。全体は 3 つの地平線で進む:

- **H1 文脈内適応** (few-shot + rubric 編集): 凍結された汎用モデルの操縦。天井は
  ベースモデル能力。移行判定 = gold set 改善が揺らぎ床に沈む (測定された飽和)。
- **H2 重みへの焼き込み** (SFT/自己蒸留): few-shot の上位互換ではなく別エラークラス
  (出力短縮×品質維持・レイテンシ) の手。焼くのは安定した形式規律のみ、ドクトリンは
  プロンプトに残す。参入条件 = few-shot で不動のエラークラスの実測 + ラベル充足。
  **具体構成・文献根拠・RL の位置づけは
  [self_improvement_literature_survey.md](self_improvement_literature_survey.md)
  の統合結論を SSoT とする (2026-08-22)** — 3 段カスケード (古典 ML ヘッド → 小型 dense
  生徒 → 凍結メイン)、学習則は KTO を第一段・RLVR (決定論報酬限定) を第二段。
  パネル・暗黙信号を重み学習の報酬にしないことは §5 不変条件 1 の拡張として不変。
- **H3 モデル可換性 (真の終着点)**: few-shot も SFT もモデル自体も交換可能な「生徒」。
  恒久資産は格子そのもの — 検証済みラベル・較正曲線・gold set・ドクトリン。
  **成功の定義: モデルを乗り換えても、(a) eval が即日で新旧を測定し (b) few-shot
  プールが文脈で再係留し (c) 必要なら同じラベルから再蒸留して、数日で判断品質が
  回復すること。** モデル更新が博打でなく測定可能なアップグレード判断になる。

この定義により、本設計の各コンポーネントの価値序列も定まる: C1 (ラベル) と C3
(較正) が恒久資産、C8 (few-shot) と将来の SFT は資産の消費形態、パネル (C2) は
資産を増やす製造装置である。

## 10. シャドー先行の原則と決定記録 (2026-08-21 追記)

### 10.1 シャドー運用原則 (全 Phase に適用)

**本設計のいかなるコンポーネントも、シャドー期間の計測を経ずに本番へ接続しない。**

- シャドー = 格子 (labels / panel_verdicts / 較正曲線) は**自分のテーブルに書くだけ**で、
  本番パイプラインは一切それを読まない。few-shot 注入・自動 rollback・自動採用ラベルの
  消費はすべて cutover 後にのみ有効化する。
- 各 Phase の完了条件を「実装完了」から「**シャドー計測完了 + cutover 判断**」に改める。
  cutover 判断は計測値 (下記) を利用者に提示して行う。
- 先例に従う: PIR shadow mode (UI のみ・logic 未注入・観察期間で採否) /
  subject-gate 型の env flag 即時 rollback を各接続点に必ず用意する。

### 10.2 外部 LLM (上級監査) の段階的検証

外部 LLM の利用は**条件付き承認** (2026-08-21)。接続は以下の実測を経てから:

1. **P3 シャドーで、まずローカル 2 モデルのみ** (26B + 8B) のパネルを裁定ストリームに
   通し、以下を数週間計測する:
   - 不一致率 (パネルが必要になる母数)
   - **分裂率 (= 外部 LLM にエスカレーションされるはずだった件数/週)**
   - 分裂サンプルのトークン量 (本文送信量の実数)
2. 計測値から**外部呼び出しの月間件数・送信トークン量・概算費用**を算出し、利用者に
   提示 → 予算 cap と接続可否を確定する (単発見積りを外挿しない)。
3. 接続後も cap 超過時はローカルのみへ自動縮退 (fail-closed)。

### 10.2b シャドー計測の初回記録 (2026-08-22、過去 90 日 backfill。同日訂正)

E1 主体ラベル全量 (56 件、body 保持 90 日が上限) でパネルを一括裁定した結果:

| 層 | 件数 | パネル結果 |
|---|---|---|
| 対照 (本番 = E1 正解) | 22 | **22/22 unanimous_correct** |
| 「係争」(本番 ≠ E1 正解) | 3 | 3/3 で パネルは E1 と不一致 (2 件は両者とも空、1 件は両者とも別の値) |
| 候補未到達 (裁定対象外) | 38 | — (構造ゲートの到達率問題として別掲) |

**訂正 (同日)**: 当初この 3 件を「全員一致の誤答 = 壁 1 の実測」と読んだが、記事本文の
突合で **3 件とも E1 ラベル側の誤り** (収穫ノイズ) と確定した — 本番とパネルの判定が
正しかった。ノイズは 2 系統・計 5/56 件 (~9%):

1. **遅延声明の窓誤結合** (3 件): 声明の時刻錨を掲載日にしていたため、発覚 3 か月後に
   掲載された声明が同一組織の**別インシデント**報道と ±5 日で結合した (LexisNexis)。
   記事側の言及は「過去事例への言及」で、主題は攻撃者未公表の新事件 — 空が正解。
   → 錨を発覚日 COALESCE(published_at, created_at) に修正。
2. **ダイジェスト除外の移植漏れ** (2 件): 多数事件まとめに単一主題は無い。eval script に
   あった除外を production 収穫へ移植し忘れた。→ 除外を移植。

**確定した含意**:
- **パネルはラベル監査として機能した** — 「パネル全員一致 × E1 と不一致」が 9% の
  ラベルノイズを 100% 精度で検出した (誤検出ゼロ: 一致 22 件は全て正ラベル)。
  E0/E1 は錨だが無謬ではない (§3 の前提どおり) — この不一致こそ C5 人間裁定の
  正しい着弾物であり、「どちらが誤りか」を人間が裁く (今回は全件ラベル側だった)。
- **真の係争 (ラベル正・判定誤) は 0 件/90 日** — 分裂率も 0%。外部 LLM の
  エスカレーション実量はゼロ近傍で、予算懸念は当面存在しない。
- P4 のトリガは「E0/E1 × パネルの不一致」(決定論) を第一とし、着弾は月 ~1-2 件想定。
  裁定 UI は最小構成でよい。
- ⚠ n が小さい。週次パネルの蓄積で継続再評価する。

### 10.2c C8 few-shot の初回実測 (2026-08-22) — cutover 見送り

judgment への retrieval few-shot 注入 (E1 プール 51 件、embedding 近傍 k=2、自己混入
ガード付き) を goldset 3 者比較 (86 件、床 = 基準 2 実行) で実測:

- **標的 subject_actor_id: 効果なし** (充足 15.1→14.0%、-1.1pt は床 ±3.9pt 内)
- **干渉劣化 2 項目**: event_date **-10.4pt** (床 ±4.3)、compromise_date -2.3pt (床 ±2.0)。
  例示に含む過去記事の文脈が日付系フィールドの抽出を妨害した
- 判断: **JUDGMENT_FEWSHOT は off のまま** (測定利得ゼロ + 回帰面ありの注入はしない —
  08-18/08-21 の「プロンプト行にはコストがある」と同じ判断)。プール・測定 harness・
  版数紐づけは資産として残す (ラベルの質と量が変わったら同じ器で再測定)
- **§9 の H1 移行判定に対する含意**: 「gold set 改善が揺らぎ床に沈む」= H1 (文脈内適応)
  の飽和シグナルの初観測。ただし n=1 手法 (few-shot) の 1 回であり、真の gap は
  候補未到達 26% (構造ゲートの到達率 — few-shot では原理的に解けない)。H2 より先に
  到達率 (feed 経路補完・辞書拡充) が効く

### 10.2d 教師伸びしろ測定 (2026-08-22) — 主要フィールドで教師≈生徒

frontier 教師 (claudecode:sonnet、bridge 経由) で凍結 goldset 86 件を summarizer /
judgment の両ターゲット実行し、現行 gemma と床付き比較 (H2 参入条件 §9 の実測):

- **judgment の核心フィールドは床内**: subject_actor_id 15.1→12.8% (床 ±3.9)、
  一致 92%。主体帰属で教師の優位は観測されず (パネル backfill の「ラベルが在る領域は
  既に正解」と整合)
- 床超えの差分は解釈が割れる: event_date +7.0pt (教師がより多く抽出、一致 59%) /
  named_primary_actor -7.0pt (教師がより保守的 — 収穫汚染の歴史からは美点の可能性)
- summarizer の大差 (bluf +25.6 / event_date +19.8 / pmesii +12.8 等) は「gemma が
  空にする任意フィールドを教師が埋める」充足パターン差。正解が無い以上「改善」とは
  呼べない。importance 一致 90%・intent 一致 77% — **不一致箇所の正誤は人間裁定
  サンプルでのみ確定可能**
- ⚠ 測定の限界: ①rationale 充足 95→50% は bridge の structured required 強制の差
  (配管差) の疑い — モデル知能の差と混同しない ②goldset は易例が支配的で、教師優位が
  あるとすれば過少代表の難例側 ③sonnet + 現行プロンプトは教師の上限ではない

**含意**: 品質目的の教師蒸留の余地は現時点で限定的。生徒モデル (H2) の第一の価値は
**速度・コスト・ループ反復の実践**に置き、蒸留元は 26B + 決定論フィルタで足りる。
品質の実効打は引き続き候補到達率 (§10.2c) と、不一致サンプルの人間裁定による
教師較正が先。

## 11. 既存運用レビューの格子への統合 (2026-08-21 承認)

既存の運用レビュー (Intel Graph operations タブ: taxonomy / editorial、および actor 承認
キュー) の精度問題 3 点 — ①証拠が件数のみで記事に到達できない ②editorial 訂正が
write-only (消費者ゼロ) ③人間裁定が較正されない — を、較正格子の部品で解消する。
統一する動きは 1 つ: **既存レビューの人間裁定をすべて tuning_labels (E3 層) に合流させる**。

| 施策 | 内容 | 乗せる先 |
|---|---|---|
| A. E3 ラベル合流 | taxonomy 採否・editorial 訂正を tuning_labels に書く producer を追加 (過去分 backfill 可)。editorial の write-only が解消し、訂正が C8 few-shot 経由で分類精度に還流 | P1 に併設 |
| B. 証拠リンク | taxonomy 提案の evidence_ids (保存済み・未表示) を ArticlePeek で開けるリンクにする | 独立・即時 |
| C. 人間裁定の事後監査 | E1 到着時に裁定を突合し override 成績を可視化 (C5 の「人間も較正される」の遡及適用)。区分1 の人間同意率を実測し、十分高ければ C7 型 (自動適用 + rollback + ops 通知) へ昇格 | P3 |
| D. 裁定 UX 統一 | P4 の裁定サブビューの「1 件 = 証拠 + 2 択」カード部品を taxonomy にも適用 | P4 |

ガード: E3 ラベルは E0/E1 より弱い強度として層別 (C3)。few-shot 投入時は rubric 版数
紐づけ (C8) を適用。

## 12. 人間非介在の縮退設計 (2026-08-21 承認)

**原則: 人間は加速材であって燃料ではない。** ループの進行 (計測・ラベル生産・few-shot
更新・自動 rollback) は E0/E1 の決定論ソースだけで自走する。人間裁定 (E3) は精度を
上げる追加供給であり、欠けてもループは減速するだけで停止しない。これを保証するため、
**すべての人間タッチポイントに「無応答時の既定挙動 (no-human default)」を定義する**。
既定は常に保守側 (現状維持 / 不採用 / 除外) で、キューは無限成長しない (§5 不変条件 9)。

### 12.1 タッチポイント別の無応答既定

| タッチポイント | 人間がいる場合 | 無応答時の既定 | ループへの影響 |
|---|---|---|---|
| C5 係争裁定 (パネル分裂) | 2 択裁定 → E3 ラベル | TTL 30 日で「未裁定」として自動アーカイブ (ラベル化せず few-shot 不投入)。**E1 が後日到着したら人間を追い越して自動確定** | 該当サンプルが学習材から欠けるだけ |
| C6 rubric 提案承認 | 承認 → 版付き適用 | 未承認のまま現行 rubric で運転継続 (現状維持は安全な定常状態)。同一 block への新提案で旧提案は superseded 自動失効 | 改善が遅れるだけ。測定・提案生成は自走継続 |
| C7 自動 rollback | — | **人間不要 (唯一の無人適用)** — 劣化防御は人間不在でも作動 | なし |
| taxonomy 提案 | 採用/却下/保留 | pending のまま週次 upsert で evidence refresh、TTL で stale 自動 expire。区分1 は同意率実測後に C7 型自動適用へ昇格 (§11-C) | 辞書更新が遅れるだけ |
| editorial 訂正 | 訂正 → E3 ラベル | 任意入力。訂正ゼロでも stance の較正は E1 (続報整合) で継続 | なし |
| ラベル自動採用 (C4 高確信帯) | **事後 veto** (来歴付き取り消し → few-shot から除去) | veto なし = 採用のまま | なし |

### 12.2 事前承認から事後拒否権への転換

- **ラベル採用は事前承認不要の自動** (C4 高確信帯)。人間は事後に veto できる。誤りの
  帰結が回復可能 (ラベル 1 件の混入は局所的で複利しない) なため、「auto-apply の誤りは
  複利」の原則 (§1) に抵触しない。veto は来歴に残し、veto 率は C3 のドリフト番兵に入れる。
- **前向き rubric 適用だけは人承認を維持** (帰結が複利するため — 不変条件 3)。ただし
  これは「承認がないと止まる」ではなく「承認がないと現状維持」であり、現状維持は常に
  安全な定常状態。ブロッカーではない。

### 12.3 キュー衛生の可観測性

- 各キューの滞留・自動アーカイブ率・TTL expire 件数を fill-rate 週次監査に登録し、
  閾値超過は ops 通知 (DB 永続 — 人間が見なくても記録は残る。「成功も記録する」原則)。
- 人間の非介在そのものは異常ではない (設計上の想定状態)。異常として扱うのは
  「自動化率が想定帯から外れる」ドリフトのみ。
