# 自己進化チューニングループ (較正格子) 設計

作成: 2026-08-21。LLM チューニングの自動化検討 (retrieval few-shot / 正解ラベル整備 /
自己進化ループの議論) の帰結をまとめた全体設計。**実装前の合意用文書** — 着手順・
コンポーネント境界・不変条件をここで固定する。

---

## 1. 目的と、自動化しないものの宣言

**目的**: プロンプト (rubric) チューニングの「測る → 例を良くする → 変更を試す → 戻す」
のループから人手作業を可能な限り除き、人間の関与を以下の 2 点に濃縮する:

1. **目的の定義** (何が high か・PIR — 真偽でなく準拠点の問題)
2. **fail-closed の拒否権** (証拠付き提案の承認 / パネルすら割れる係争の裁定)

**自動化しない理由が原理的なもの (3 つの壁)**:

- **壁 1 — 相関した盲点**: 全 LLM は重なった学習分布を共有し、新奇事象・ローカル文脈・
  稀少クラスで誤りが相関する。多様パネルは壁を細らせるが消せない。かつ本ツールの
  致命的失敗 (稀少 high の取りこぼし) はまさにこの領域にある。
- **壁 2 — 規準の問題**: 重要性の定義はドクトリンの事実であり、投票では到達できない。
- **壁 3 — 合意 Goodhart**: パネル合意率を最適化目標にすると、システムは「モデル間
  コンセンサス = Web の平均事前分布」へドリフトする。合意は routing にのみ使い、
  **報酬 (最適化の目標関数) には決して使わない**。

**人間も oracle ではない** (バッチ承認事故 07-26、測定誤りの実績)。人間を残す根拠は
正確性ではなく: ①誤りの脱相関 (Web コーパス外の判定器) ②帰結の非対称 (veto の誤りは
回復可能、auto-apply の誤りは複利) ③責任の非委譲性。**人間の裁定も較正対象とする**
(遅延正解による事後監査)。

## 2. 設計原則 (既存原則との接続)

| 原則 | 本設計での適用 |
|---|---|
| 指示より決定論的関門 | 適用 (apply) は人承認のみ・rollback だけ無人、を code で強制 |
| 承認キュー 3 原則 (起票→レビュー UI→承認=適用の終端保証) | 提案・係争の両キューに適用 |
| 成功も記録する | パネル裁定・人間裁定・自動採用のすべてに来歴と結果を永続化 |
| 対照群なしでは何も言えない | 全評価は 基準1/基準2(対照)/変種 の 3 者比較 (gold set 既設) |
| 母集団の反転 > フィルタ追加 | ラベルは「LLM 出力の採点」でなく「外部正解との突合」を起点に定義 |
| ICD 203 (確度の規律) | 運用者自身の裁定にも適用 (override の事後成績を可視化) |

## 3. 全体アーキテクチャ: 較正格子

正しさはどの単一ノードにも宿らない。強い順に並ぶ「すべて誤りうる証拠源」が、
重なる領域で相互較正する格子として全体を構成する。

```
[E0 決定論的事実]  feed 帰属 (犯行声明)・引用実在チェック・schema/辞書ゲート
      │  (最強。ここだけが無条件の錨)
[E1 遅延正解]      後日の MITRE 帰属確定・dedup クラスタでの続報整合・
      │            PIR 事後マッチ・訂正報道 — 「未来が過去の判定を裁く」
[E2 多様パネル]    異系統モデル群 + 条件付け (盲検再判定・摂動安定・含意分解)
      │            E0/E1 と重なる層で 合意度×実正解 の較正曲線を常時測定
[E3 人間裁定]      パネル分裂のみ着弾。裁定は E1 で事後監査 (人間も較正される)
[E4 ドクトリン]    PIR・rubric の意図。機械は「誤り」を問えないが
                   「内部不整合」「現実との乖離」(PIR 逆転検出の実例) は指摘する
```

**確信度ルーティング** (格子の出力):
- 高確信帯 (較正曲線で実測された帯) → 自動採用 → ラベル化・few-shot プール供給
- パネル分裂・低確信 → E3 (人間キュー) へ
- E1 未到着で確定不能 → 「係争中」として保持 (即断しない)

## 4. コンポーネント設計

### C1: 遅延正解の収穫 (格子の燃料) — 最初に作る
- 週次ジョブ。「当時の判定 vs 後日確定した事実」を突合し `tuning_labels` に書く。
- 初期ソース: ①feed 帰属×ニュース記事 (victim_org ±5 日突合 — 実証済み手法) ②MITRE
  週次同期での帰属確定 ③dedup クラスタ内の判定不整合 ④PIR 事後マッチと importance の乖離。
- テーブル: `tuning_labels(id, article_id, field, label_value, source(E0..E3), strength,
  arrived_at, provenance, superseded_by)`。**新列 3 点セット規約に従い、消費者 (C3/C8) を
  同時に実装**する。

### C2: 多様パネル裁定
- 陪審: Gemma 26B (現用) + Llama 3.1 8B (安価な異議者) + 外部 LLM (分裂時の上級監査、
  ティア明示割当 + 予算 cap)。§4 denylist 準拠はモデルティア既存 3 層防御に乗る。
- 条件付け: 盲検 (元判定を見せず証拠のみ) / 摂動再判定 (言い換え安定性) / 含意分解
  (根拠引用の実在は E0 チェック、引用→主張の含意のみ問う)。
- **呼び出し点は 2 つだけ**: ①raw 不一致・係争の裁定 ②rubric 変種の評価。
  per-article には使わない (コスト不変条件 §6)。

### C3: 較正層
- E0/E1 が存在する層で「パネル合意パターン × 実正解率」の較正曲線を層別に維持。
- 外挿 (正解のない層への適用) は**明示された仮定**として文書化し、ドリフト番兵
  (合意率分布の変化検知) を常設監査に登録する。

### C4: 確信度ルーティング (§3 のとおり)

### C5: 人間裁定キュー + 人間の較正
- 着弾はパネル分裂のみ (全不一致の 1 桁減を見込む)。1 日 5 分 cap。
- 裁定環境の設計自体が精度変数: 証拠の提示・2 択化・バッチ承認の抑止 (07-26 教訓)。
- 人間裁定も E1 到着時に事後監査し、override 成績を可視化する。

### C6: 提案生成 + 自動評価
- LLM が不一致サンプルから rubric 改善案を起案 → gold set 3 者比較を自動実行 →
  「効果 X (揺らぎ床 ±Y)・回帰面ゼロ」の証拠付き提案としてキューへ。
- **適用は人承認のみ** (版履歴付き block 編集として — 層分け基盤に乗る)。

### C7: 自動 rollback 関門 (唯一の無人適用)
- cutover 後の週次指標が劣化したら該当プロンプトを前版へ自動復帰 + ops 通知。
- fail-closed 方向のみ無人、が本設計で唯一の自動適用。

### C8: few-shot プール管理 (retrieval few-shot の実体)
- 高確信ラベル付き事例を embedding 近傍検索 (dedup 用 arctic-embed2 基盤を流用) で
  k=2-3 件、composer の例示層へ code 所有の動的注入。
- 例に **rubric 版数を紐づけ**、版を跨いだら無効化 (旧基準を教えない)。
- 例プールにも層化を適用 (稀少クラスの偏り防止)。

## 5. ガバナンス不変条件 (違反 = 設計違反)

1. パネル合意は routing 専用。**最適化の目標関数に使わない** (壁 3)。
2. ループの報酬・合否判定は E0/E1 層のみに錨を打つ。
3. 前向き適用 (rubric 変更) は人承認のみ。無人適用は rollback (後ろ向き) だけ。
4. すべての裁定 (自動・パネル・人間) に来歴を残し、E1 で事後監査可能にする。
5. 評価は常に 3 者比較 (対照群必須)。
6. per-article のパネル呼び出し禁止 (LLM 時間予算の保護)。
7. モデル選定は §4 denylist / ティア 3 層防御に乗る。外部 LLM は明示割当 + 予算 cap。

## 6. 段階的実装計画

| Phase | 内容 | 完了条件 |
|---|---|---|
| P1 | C1 遅延正解収穫 + tuning_labels + 消費者としての簡易表示 | 週次でラベルが自動蓄積し、種別ごとの件数が UI で見える |
| P2 | C6 後半 (gold set 3 者比較の cron 化) + C7 自動 rollback | rubric 変更の翌週に自動で合否が出て、劣化時に無人で戻る |
| P3 | C2 パネル + C3 較正曲線 (E0/E1 層で測定開始) | 合意度×正解率の曲線が層別に出る |
| P4 | C4 ルーティング + C5 人間キュー (裁定 UI) | 不一致の大半が自動裁定され、人にはパネル分裂のみ届く |
| P5 | C8 few-shot 注入 (judgment から) + C6 前半 (提案生成) | 3 者比較で few-shot の効果が測定され、証拠付き提案が届く |

各 Phase は独立にデプロイ可能・独立に rollback 可能とする。P1-P2 は既存部品の組合せで
小さく、P3 以降が新規性の中心。

## 7. リスクと未解決問題

- **外挿仮定の検証不能性**: 較正曲線の「正解のない層への転移」は原理的に検証できない。
  緩和はドリフト番兵と、稀少クラスを常に E3 (人間) 側へ倒す保守ルーティングのみ。
- **パネルのコスト/時間**: 分裂率が想定より高いと E3 が溢れる。P3 で実測してから
  P4 の閾値を決める (単発見積りを本番に外挿しない)。
- **ドクトリン変更時の較正リセット**: PIR/rubric の大改訂は較正曲線と few-shot 例の
  前提を壊す。版数紐づけで自動失効させるが、失効直後は自動採用帯が縮む (仕様)。
- **稀少クラスの標本不足**: high・日本標的の較正は標本が集まりにくい。層化と
  「不足層は自動化しない」の明示が必要。

## 8. 着手前に利用者の決定が要る事項

1. **外部 LLM (パネル上級監査) の使用範囲**: 記事本文が外部送信される。ティア明示
   割当の枠内だが、パネル用途への割当可否と月間予算 cap。
2. **裁定 UI の置き場**: 既存レビューキュー群 (承認 UI) への統合で良いか。
3. **P1 の遅延正解ソースの優先順**: 上記 4 種のうちどれから始めるか (推奨: ①feed 突合
   ②MITRE 確定 — いずれも決定論で実装が軽い)。

## 9. 終着点: この設計が向かう先 (2026-08-21 追記)

few-shot は終着点ではなく H1 の技法である。全体は 3 つの地平線で進む:

- **H1 文脈内適応** (few-shot + rubric 編集): 凍結された汎用モデルの操縦。天井は
  ベースモデル能力。移行判定 = gold set 改善が揺らぎ床に沈む (測定された飽和)。
- **H2 重みへの焼き込み** (SFT/自己蒸留): few-shot の上位互換ではなく別エラークラス
  (出力短縮×品質維持・レイテンシ) の手。焼くのは安定した形式規律のみ、ドクトリンは
  プロンプトに残す。参入条件 = few-shot で不動のエラークラスの実測 + ラベル充足。
- **H3 モデル可換性 (真の終着点)**: few-shot も SFT もモデル自体も交換可能な「生徒」。
  恒久資産は格子そのもの — 検証済みラベル・較正曲線・gold set・ドクトリン。
  **成功の定義: モデルを乗り換えても、(a) eval が即日で新旧を測定し (b) few-shot
  プールが文脈で再係留し (c) 必要なら同じラベルから再蒸留して、数日で判断品質が
  回復すること。** モデル更新が博打でなく測定可能なアップグレード判断になる。

この定義により、本設計の各コンポーネントの価値序列も定まる: C1 (ラベル) と C3
(較正) が恒久資産、C8 (few-shot) と将来の SFT は資産の消費形態、パネル (C2) は
資産を増やす製造装置である。
