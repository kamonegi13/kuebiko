### 3. 選好最適化

| 手法 | 出典 | 核心 | 適用性 |
|---|---|---|---|
| DPO (2023) | [arXiv:2305.18290](https://arxiv.org/abs/2305.18290) | pairwise 選好から報酬モデルなしで直接最適化 | **条件付き** — pairwise 調達コストが供給者 1 名と相性悪。教師合成で補えば可 |

| ORPO (2024) | [arXiv:2403.07691](https://arxiv.org/abs/2403.07691) | SFT+整合を単一化、reference model 不要で省メモリ | **条件付き** — 単一 Mac に好適だが pairwise 調達は DPO と同課題 |
| SimPO (2024) | [arXiv:2405.14734](https://arxiv.org/abs/2405.14734) | reference 不要・平均対数確率を暗黙報酬に | **条件付き** — 同上 |

### 4. 少数データ SFT と忘却 (実施時の警告 3 点)

| 知見 | 出典 | 本件への警告 |
|---|---|---|
| LoRA Learns Less and Forgets Less (2024) | [arXiv:2405.09673](https://arxiv.org/abs/2405.09673) | LoRA は full FT より忘却が少ない — が、実証規模は **10 万ペア** (本環境の実データの 2 桁上)。「やるなら LoRA」の補強にはなるが小データでの保証ではない |
| Tool-use SFT の忘却 / InfoSFT (2026) | [arXiv:2605.14967](https://arxiv.org/abs/2605.14967) | **4,000 件の特化 SFT でも既存能力の顕著な忘却**。特化フォーマット (JSON schema) 学習はまさに高リスク型 — 低学習率・部分 freeze 等の緩和とセットが必須 |
| Schema Reinforcement Learning (2025) | [arXiv:2502.18878](https://arxiv.org/abs/2502.18878) | 通常 SFT は schema 追従を汎化できず、**schema validator を報酬にした RL の方が汎化を保つ**。schema 検証は本環境が無限に生成できる決定論報酬 — 重要な設計指針 |

### 5. MLX / Apple Silicon の実務 (工学的ボトルネック)

- **学習**: MLX は LoRA/QLoRA をネイティブ対応。MoE 層は公式でなくサードパーティ実装
  (per-expert LoRA) 依存で安定性は要検証。M3 Max 級で 27B 4-8bit + LoRA の実行報告あり
  (非査読)。学習入力は safetensors 必須 (GGUF は推論専用)。
- **配信**: Ollama の `ADAPTER` 公式対応は Llama/Mistral/Gemma 1-2 のみ。llama.cpp の
  LoRA→GGUF 変換は新しい MoE アーキテクチャへの追従が遅い
  ([既知 issue](https://github.com/ggml-org/llama.cpp/issues/3953))。
  **「学習できたが配信できない」ギャップが現実のリスク** — 回避はアダプタ配信でなく
  LoRA をベースにマージしてフル重み gguf を再ビルドする経路。

### Part 1 の結論 (この構成に効く順)

1. **KTO** — 本環境のフィードバック構造 (二値・不均衡・単一供給者) に構造的に一致。
   量は教師合成ラベルで補うハイブリッドが実装条件
2. **検証可能サブタスク限定の ReST-EM/STaR 型自己訓練** — 既存の決定論検証器
   (E1 突合・schema・IOC 正規表現・辞書) を報酬フィルタに、300 件/日を学習データ化
3. **教師による KTO/DPO ラベル・rationale 合成** (Zephyr 型) — 供給者 1 名の実質解。
   gold set で教師ラベルの信頼性を較正するゲートが必須 (自己増幅リスクの遮断)
4. **更新方式は KTO/ORPO 系を優先し、フル SFT を避ける** — 忘却 3 論文の一致した示唆
5. **LIMA 型「量より質」の継続** — 勾配更新に先立つ低リスクレバー。本ツールが既に
   実証した成功パターンの継続であり、1-4 の検証中の安全な現状維持戦略

### 8. LLM-as-judge の信頼性 (本件で最重要の領域)

| 手法 | 出典 | 核心 | 適用性 |
|---|---|---|---|
| PoLL (2024) | [arXiv:2404.18796](https://arxiv.org/abs/2404.18796) | 異系統 3 モデルの小パネルが単一 GPT-4 判定を上回りコスト 1/7 | **適用可** — 現行の別系統 2 モデルパネルはこの縮小版。用途拡張時は 3 系統目を検討 |
| Nine Judges, Two Effective Votes (2026) | [arXiv:2605.29800](https://arxiv.org/abs/2605.29800) | 9 judge パネルの名目独立性の**約 3/4 が誤り相関で失われ**実質 2 票分。judge 追加や集約工夫はギャップの最大 11% しか埋めない | **適用可 (最重要の裏付け+警告)** — 「一致×外部正解との不一致=ノイズ検出」は理に適うが、**パネルを importance 等の多数決スコアリングに昇格させる理論的根拠は無い** |

### 10. in-context 例示の選択と干渉 (few-shot 棄却の文献的裏付け)

| 知見 | 出典 | 適用性 |
|---|---|---|
| Rethinking Demonstrations (Min+ 2022) | [arXiv:2202.12837](https://arxiv.org/abs/2202.12837) | **適用可 (強い裏付け)** — few-shot の効果は正しいラベル対応でなく**ラベル空間・入力分布・フォーマット**由来。「required 全指定が効き、散文追記と few-shot は効かなかった」本ツールの実測と一致 |
| KATE (2021) | [arXiv:2101.06804](https://arxiv.org/abs/2101.06804) | **条件付き** — kNN 検索例示は生成系で +40% 級の改善報告。ただし Min+ と併読すると効果の本体は分布・フォーマットの一致 |

### 11. 較正・CTI ドメイン

- **Conformal Risk Control** ([arXiv:2606.29054](https://arxiv.org/abs/2606.29054)):
  **条件付き** — 較正には正解ラベルが必須のため、適用可能なのは E1 チャネルのみ。
  正解不在フィールドには原理的に適用不可
- **CTIBench** ([arXiv:2406.07599](https://arxiv.org/abs/2406.07599)、NeurIPS 2024):
  closed-book 知識テストで gold set 転用は不可。ローカルモデルの CTI 知識の絶対水準
  (特に脅威アクター帰属の弱さ) を年次で外部チェックする用途に有用
- **CTIConnect** ([arXiv:2510.11974](https://arxiv.org/abs/2510.11974)、KDD 2026):
  専門家検証 1,860 QA・RAG 設定。分布が異なり gold 転用不可、参考実装として有用

### Part 2 の結論 (報酬配線を太くする順)

1. **UI 閲覧行動の計装** (開く/翻訳/ブックマーク) — 供給量を桁で増やす構造的に唯一の
   経路。ImplicitRM の警告 (開かない≠負例) を最初から設計に織り込む
2. **遠隔監督の複線化** (Snorkel 型) — LF を 1 本→複数の独立ヒューリスティクスにし、
   検出止まりから「LF の修復」へ
3. **パネルの用途を「ノイズ検出」に厳格限定する設計ガード** — 誤り相関の文献 2 本は
   「一致の多数決化」に理論的根拠が無いことを示す。分裂率 0% は独立性でなく相関の
   証拠と再解釈しておく
4. **few-shot 変更の実測 A/B を標準工程化** — 効果の方向は予測不能 (実測済みの棄却と一致)
5. **較正付き abstention を E1 チャネル限定で** — 適用範囲は狭いがノイズ率をさらに下げる

### 推奨アーキテクチャ: 凍結メイン + 学習で重みが動く小型生徒のカスケード

**日常の判定パス (リアルタイム、3 段カスケード):**

```
記事 (RSS/Grok/scraper)
  → 決定論前処理 (候補ゲート: 辞書×本文言及 + feed 候補補完 / IOC regex / routing)
  → [ヘッド: embedding+古典分類器 (~1ms、較正確率つき、秒単位で再学習)]
      ├ 固定語彙の明白な分類 (category/stance/明白な low triage) → 確定
      └ それ以外 ↓
  → [生徒: 小型 dense LLM、LoRA 週次更新] が構造化判定
      ├ 確信高 (較正済み帯 C3/C4、goldset で生徒≧メイン実証済みの範囲) → 採用
      └ 確信低・稀少クラス (high/日本標的 等は常時) → [メイン 26B/31B (凍結)]
  → BLUF 整形 (生成タスクは常にメイン) → Discord / Web UI
```

**週次の学習ループ (バックグラウンド自走):**

```
蓄積   判定 ~300 件/日 + E1 遅延正解収穫 (水) + E3 人間裁定 + (拡張) 閲覧計装
評価   goldset 3 者比較 (土) + シャドーパネル (日) + 週次ガバナンス (月)
学習   報酬 3 層 (決定論検証器 > 較正済み教師 > 人間監査) → KTO/ReST-EM で
       生徒の LoRA を更新 (MLX、数十分/回)
関門   goldset 合否 → シャドー一致率 → cutover 拡大 or C7 rollback
係争   E1×パネル不一致 → 裁定キュー (人間 2 択、月数件) → E3 ラベル化
```

**役割分担 (H3 の可換性そのまま):**

| 構成要素 | 役割 | 重み |
|---|---|---|
| ヘッド (古典 ML) | 固定語彙分類・較正確率・能動学習の土台。**秒単位で再学習** | **可変** (最速のループ) |
| 生徒 (小型 dense LLM) | 量産の構造化判定。週次の学習対象 | **可変** (LoRA) |
| メイン 26B/31B | 検証者・難例担当・生成タスク・蒸留元 | 凍結 |
| 外部 frontier (任意) | 較正済み範囲での教師ラベル・上級監査 | — |
| 人間 | 監査・拒否権 (2 択裁定・rubric 承認)。週数分 | — |
| 恒久資産 | ラベル + 較正曲線 + goldset — モデル交換後も残る | — |

### 古典 ML 層の位置づけ (2026-08-22 追記)

LLM は「1 記事を深く読む」装置、古典 ML は「全記事・全履歴を ~ms で何度でも測る」装置。
役割は 2 系統ある:

**(a) 置き換え (蒸留ヘッド)** — 固定語彙分類 (category/stance/article_type、triage の
明白な low 足切り) を、既存 DB の LLM 判定 (~1 万件超) + 既存 embedding 基盤から蒸留。
新規ラベリング不要で即日作れる。利点は LLM に対して原理的: **決定性** (揺らぎ床が消える) /
**真の較正確率** (C4 ルーティングの理想入力 — LLM の自己申告 confidence は較正されていない) /
**再学習が秒単位** (ループが日次で回る) / 推論 ~1ms。上限は蒸留元 LLM の品質 (誤りごと圧縮
する) — 価値は品質でなく速度・決定性・較正・ループ実践に置く。rubric 版数に紐づけて
版が動いたら再蒸留 (few-shot プールと同じ規律)。

**(b) 新規に可能になるタスク (集合レベル — per-article LLM では原理的に不可能)**:

| 新タスク | 中身 | ラベル | 価値 |
|---|---|---|---|
| バースト/異常検知 | アクター/セクター/国別の言及・被害ストリームへ変化点検出・異常度。個々の記事に書かれていない「集合の変化」を I&W シグナル化 | **不要** | 高 |
| キャンペーンクラスタ | embedding 密度クラスタリングで週〜月スパンの関連記事群を追跡対象化 (dedup のペア判定を超える) | **不要** | 中〜高 |
| 能動学習 | 較正確率の不確実性サンプリングで「人間の 2 択裁定に最も情報価値の高い事例」を選ぶ — 週数分の人間予算の情報効率を数倍化 (§12 の「加速材」の最大効率運用) | 既存 | 高 |
| 閲覧ランキング | 閲覧計装 + learning-to-rank で表示順を個人化。**表示順のみ — フィルタには使わない** (何が重要かは PIR ドクトリンが正。行動ログへの委譲は合意 Goodhart と同型の罠) | 暗黙 | 中 |

上 2 つはラベル不要 — 本調査で一貫した制約「正解の希少性」を回避して今あるデータだけで
立つ新能力である点が重要。

### 強化学習の位置づけ (2026-08-22 追記)

RL は**入っている — ただし「オンライン PPO 型」ではなく安定側の変種を段階的に**:

1. **第一段 (採用): DPO/KTO = RLHF 目的関数の閉形式解** — DPO は KL 制約付き報酬最大化
   (RLHF の目的関数そのもの) をオンライン試行錯誤なしに解く直接最適化であり、系譜として
   オフライン RL。KTO も同様。ReST-EM/STaR は方策反復のオフライン近似 (自己生成 →
   検証器フィルタ → 焼き込み)。
2. **オンライン RL (policy gradient) を最初から使わない理由**: ①学習された報酬 (パネル・
   暗黙信号) を最適化対象にすると報酬ハッキングが起きる — 本設計の壁 3 (合意 Goodhart)
   が禁じた「合意を目標関数にする」への滑り込みそのもの ②標本効率と安定性 (単独運用の
   データ規模・単一 Mac で PPO 系は成立しない) ③文献上 DPO/KTO がオフラインで同等性能。
3. **第二段 (将来枠): RLVR (検証可能報酬の RL)** — schema validator・E1 突合・辞書一致の
   ような**決定論検証器はハックされにくい報酬**であり、この領域に限れば真のオンライン RL
   (GRPO 系) が生徒 v1+ の拡張として成立しうる (Schema RL, arXiv:2502.18878 の示唆)。
   参入条件 = KTO 生徒がシャドーで安定してから。報酬は決定論検証器のみに限定し、
   パネル・暗黙信号は決して報酬にしない (§5 不変条件 1 の重み学習への拡張)。

- **効率**: 実測では判定の大半が易例 (パネル対照 22/22 全員一致)。生徒が 7-8 割を
  担えばメイン呼出が数分の一になり、LLM 2.2h/日の過半 (per-article 57%) が縮む。
  ⚠ 「生徒ドラフト→メインが常時後処理」の形は prefill が消えず効率化しない。
  さらに誤ドラフトの文脈注入はアンカリングで品質を下げる方向 (few-shot 干渉 -10.4pt と
  同型の実測あり) — **文脈注入でなく役割分担**が正しい配線
- **品質**: ドラフトが品質を上げる条件は「メインの持たない情報を運ぶ」こと。特化学習
  済み生徒がフィールド単位で goldset 実証 (生徒≧メイン) を出した範囲だけ cutover を
  広げる — 効率と品質は同じカスケードの両面で、確信度ルーティング (C3/C4) と goldset
  関門という既設の器で駆動する
- **工学的根拠**: 小型 dense は MLX / llama.cpp とも一級サポートで「学習できたが配信
  できない」ギャップ (Part 1 §5) を回避。4B 級の LoRA は M5 Max で数十分 → **週次で
  学習ループが回る**

### 強化ループの形 (蓄積 → 判断 → フィードバック → 更新)

- **動く重みは生徒のみ** (メインは凍結の検証者 = 生徒が壊れても本番は劣化しない)
- **報酬源は 3 層** (強い順):
  1. 決定論検証器 — E1 突合・schema validator (Schema RL)・IOC 正規表現・辞書一致。
     無限に生成でき、ReST-EM/STaR 型フィルタ自己訓練の燃料になる
  2. 外部教師 — スケールする教師。ただし §10.2d の実測どおり現時点の優位は限定的で、
     「教師が単に強いだけ」交絡 (arXiv:2402.12366) もある。**教師ラベルは E1 gold で
     フィールド別に較正してから許可** (不一致箇所の人間裁定サンプルが較正データ)
  3. 人間 — ラベル生産者ではなく**監査・拒否権** (§12)。週数分の 2 択裁定。
     量的教師役は 1 名では不可能であり、求めない
  4. (拡張) 暗黙フィードバック — UI 閲覧計装 (Part 2 結論 1 位)。「開かない≠負例」の
     露出補正を最初から設計に入れる
- **学習則**: KTO (二値・不均衡耐性 — 本環境のフィードバック構造に最一致) を軸に、
  検証可能タスクは ReST-EM 型。フル SFT は避ける (忘却 3 論文の一致した警告)
- **ゲートは全て既設**: goldset 3 者比較 / シャドー一致率 / C7 rollback / 裁定キュー

### 実測が決めた優先順 (2026-08-22 改訂 — 古典 ML 層を織り込み)

1. **候補到達率の改善** (feed 経路の候補補完・辞書拡充) — 最大の実測 gap (未到達 38/63)。
   どの学習手法でも解けない構造ゲートの問題で、決定論改修で確実に効く
2. **ヘッド v0** — triage/category の蒸留ヘッド (既存 DB + embedding、新規ラベル不要) を
   作り goldset で一致率・較正を実測。**カスケード運用の型を最小リスクで確立**し、
   能動学習の前提 (較正確率) を得る。LoRA 生徒より先 (新規ハード経路が不要)
3. **バースト/異常検知** — ラベル不要の新能力。I&W への統計シグナル供給
   (**2026-08-22 実装**: `src/forecast/burst.py` — 既存 forecast 器の日次拡張。
   actor 言及 + victim sector/country の日次ストリームに z-score 検出、朝ブリーフ
   「急増検知 (I&W)」節 + forecast_indicators period_type='daily' で 7 日 close-out。
   初回ドライ実測でアクター 4 件検出 — apt29 z=3.3 ⚑PIR / head_mare z=6.8 等)
4. ~~**教師の較正**~~ — **2026-08-22 実施済み・subject_actor では棄却** (設計書 §10.2e)。
   E1 錨つき母集団で main 2 回 + 教師の 3 者比較 → **全員 100% / 不一致 0** (天井効果で
   識別力なし)。教師ラベルを報酬源にしない。⚠ 錨の無いフィールド (intent / stance /
   event_date) は不変条件 13 によりパリティ止まりで、判断材料自体が無い (保留)
5. **UI 閲覧計装** — 報酬の絶対量を桁で増やす唯一の経路 (露出補正込みで設計)
6. **LoRA 生徒 v0** — ヘッドで cascade の型が確立してから。KTO で蒸留、
   将来 RLVR (決定論報酬限定) へ拡張
7. **遠隔監督の複線化** (Snorkel 型)・キャンペーンクラスタ

few-shot・パネル多数決化・フル SFT は実測/文献により**不採用を記録済み** (理由ごと
§10.2b/c と本文書の各判定に残す — 再検討時はまず同じ器で再測定する)。
