# 単一事象の追跡と、積み重ねの追跡の分離 — 設計 (2026-09-19)

## 0. 要約 (BLUF)

追跡の単位は 2 種類あり、**現状は積み重ね型が event として開設され、更新枠の 45% を消費している**。
積み重ね型を standing (常設情報要求) へ移し、event は単一事象に限る。
測定と実害は [docs/research/llm_training/SYNTHESIS.md](research/llm_training/SYNTHESIS.md) §52。

| | 単一事象の追跡 (event) | 積み重ねの追跡 (standing) |
|---|---|---|
| 境界 | 出来事そのもの | 問い・主題 |
| 続報の意味 | その出来事の姿が埋まる (被害範囲・原因・帰属) | 別の出来事が足されて趨勢が動く |
| 終わり | 判明しきれば閉じる | 閉じない |
| 開設経路 | detect (LLM + ML 前段) | 問いの起草 → 資格判定 → 昇格 (`question_store.promote`) |
| 証拠の入り方 | 決定論の matcher (anchor/entity) | 宣言的な証拠条件 (直接 + 間接の 2 本腕) |
| 評価 | 審判の `trackable` (記事単位) | 問いごとの証拠供給率・答えが動いた回数 |

## 2. 要る仕組み

1. **問いの型の追加** (`question_frame.py`):
   - `escalation` 「{subject_a}と{subject_b}の対立は{stage}の段階へ進むか」(群 B)
   - `propagation` 「{origin_policy}は{target_country}の{target_scope}へ波及するか」(群 A の MATCH 法)
2. **event → standing の移行手順** (スクリプト):
   - 問いを `question_store.promote` で登録 (config_store key=standing_questions、版履歴あり)
   - 旧 event の証拠 (`situation_evidence`) を新 standing へ付け替え
   - 旧 event を `closed` にし、`delta_note` に移行の記録を残す (墓標。アクター辞書の merge と同形)
   - **revision は移さない** (問いが変わるため答えの履歴は引き継げない。初回評価からやり直す)
3. **detect 側の整理**: 審判・ML の評価対象から積み重ね型を除く。地政学の記事が
   「1 本で完結」と判定されるのは**正しい** (§52)。

## 3. 効果の測り方

- event の再評価繰越 (`stateful_reassess_deferred` の deferred) が減るか。現状 20-75 件/run
- standing の問いごとに「証拠供給率」(24h で証拠条件に当たった記事数) と「答えが動いた回数」
- 総括の質は既存の凍結審判 15 窓で回帰を見る
